## 部署方式

服务目录仍为 `/opt/gulupai`，Compose 项目名称仍为 `deploy`，数据库及上传文件分别使用 `deploy_pgdata`、`deploy_files` 卷。公网只发布代理 TCP 80/443，应用8080和数据库5432留在容器网络内。

新服务器无法直接连接 Docker Hub，因此从原服务器导出镜像后通过 SSH 离线加载，没有替换为其他来源或其他版本。`compose.lock.yml` 使用已经校验的镜像 ID 并设置 `pull_policy: never`，原服务器的锁定文件保存在 `compose.source.lock.yml` 及 `images.source.lock.env` 中。

在新服务器执行：

```bash
cd /opt/gulupai/deploy
docker compose -f compose.yml -f compose.ip.yml -f compose.lock.yml ps
docker compose -f compose.yml -f compose.ip.yml -f compose.lock.yml logs --tail 100 app
docker compose -f compose.yml -f compose.ip.yml -f compose.lock.yml up -d --no-build --pull never
```

更新版本时需要先从可构建环境传入新镜像、核验标识并更新锁定配置。本次离线部署无需在服务器重新构建 JAR。不要重复运行默认命名的 demo-seed，也不要使用 `down -v` 删除业务卷。

## HTTPS 与续期

为 `124.220.167.12` 单独签发可信 IP 证书，未复用原 IP 的证书。HTTP 80 正常跳转 HTTPS；80还承担 HTTP 证书校验，应持续允许公网访问。

`gulupai-cert-renew.timer` 与原服务器一样，每小时检查一次证书续期，成功后由脚本重新加载 Caddy。新服务器能访问 Let's Encrypt 正式服务；测试服务出现连接重置/超时，因此续期验证改为一次正式续期，并验证代理加载新证书后的 HTTPS。

```bash
systemctl list-timers gulupai-cert-renew.timer
journalctl -u gulupai-cert-renew.service --since yesterday
```

手动常规检查使用 `./renew-ip-certificate.sh --no-random-sleep-on-renew`；Certbot 自行判断是否需要续期。不要日常使用 `--force-renewal`，本次仅用于完成真实续期验证。
