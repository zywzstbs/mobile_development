## 已开放的注册

- 学生注册：开放。
- 教师申请：开放，通过审核前登录返回 `403 / ACCOUNT_PENDING_REVIEW`，通过后获得基础 `TEACHER` 角色。
- 开放学校：`school_demo_full`，演示大学。
- 注册指纹：使用独立生成并持久保存的指纹密钥，key-id 为 `registration-p62-v1`，未修改原业务加密密钥。
- 新注册密码长度8–64，账号4–32位，以字母开头，只允许字母、数字、下划线；已有账号登录规则及密码不变。

注册不会自动加入课程/项目；教师基础角色也不会自动取得某门课程的教学权限，后续仍使用课程认领或授权流程。

匿名 `POST /auth/registrations` 需要 `Idempotency-Key`。响应只有注册回执，不返回登录令牌；其中 `id` 是申请ID。完整字段和请求示例见 [Android 接入](../docs/frontend/联调接入.md) 与 [P62接口交接](../docs/修改2/P62_注册与体验修复_后端接入说明.md)。

## 教师审核操作

在124服务器的运维终端执行。应用依据实际系统用户 `app` 匹配制品内 `cli-operators.yml`，审核审计主体固定关联 `user_demo_full_operator`（现有运营账号 operator1）。业务账号密码不提供远程审核入口；主机运维者通过 SSH/Docker 调用 CLI，人员追踪同时依赖主机登录审计。

查看待审核申请：

```bash
cd /opt/gulupai/deploy
docker compose -f compose.yml -f compose.ip.yml -f compose.lock.yml exec -T app \
  java -Xms32m -Xmx160m -jar /app/app.jar \
  --spring.profiles.active=cli --app.cli.command=list-registrations
```

确认申请ID、当前revision与教师资料后审核：

```bash
docker compose -f compose.yml -f compose.ip.yml -f compose.lock.yml exec -T app \
  java -Xms32m -Xmx160m -jar /app/app.jar --spring.profiles.active=cli \
  --app.cli.command=review-registration \
  --app.cli.application-id=<申请ID> --app.cli.expected-revision=<当前版本> \
  --app.cli.decision=APPROVE --app.cli.reason="已完成身份核对"
```

拒绝使用 `--app.cli.decision=REJECT`，填写实际理由。不要传 `--app.cli.actor` 或临时覆盖 operators，服务会拒绝；改变审核主体需要更新受保护配置并重新构建制品。待审查询会显示核验说明，只在受控运维环境处理。

学校开关可使用同一 CLI 的 `--app.cli.command=school-registration --app.cli.school-id=school_demo_full --app.cli.enabled=true|false`。全局开关和独立指纹密钥已写入服务器 `.env`，由 Compose 明确传给应用。
