# P62 注册与体验修复：后端接入说明

日期：2026-11-04。客户端 `1.0.3 / versionCode63`，正式包名 `com.grupi.app`，继续使用 `https://18.166.212.12/api/v1`。

**这是本轮新增接口与现有差异的交接契约，不代表服务器已经实现。** 当前工作区仅有客户端和文档，没有业务服务端源码。学生/教师注册和代建编辑必须由服务端部署本文件的接口后才能完成真实联调；客户端不会以本机假账号或假保存替代。

用户已明确选择：学生和教师均可注册，教师资格另行审核。该决定取代旧“全部账号只能由后台名单开户”的注册入口限制；原有课程资格、学校事实、教师认领、管理员授权、成绩和成员权限规则继续有效。

## 2. 匿名读取注册选项

`GET /auth/registration-options`

- 必须允许未登录访问。没有 Bearer、Cookie、幂等头，不应触发会话刷新。
- 仅公开允许注册的学校名称/ID与开关，不返回学生名册、教师名单、工号、密码或业务数据。
- `schools` 为完整数组，最多1000项，ID唯一；数量超限时需要先约定分页，不能静默截断。
- 关闭注册也正常返回200及开关false；没有学校时返回空数组，客户端禁用提交。

```json
{
  "code": "OK",
  "message": "成功",
  "data": {
    "enabled": true,
    "teacherApplicationEnabled": true,
    "schools": [{"id": "school_example", "name": "示例大学"}]
  }
}
```

当前 AWS 的 `GET /schools` 要求登录，不能直接拿它作为注册页的匿名学校来源。新增注册路径应加入匿名安全白名单，保留其他业务接口认证。

## 3. 提交注册

`POST /auth/registrations`

匿名；客户端发送 `Idempotency-Key` UUID 和 `X-Request-Id`，不带旧账号 Authorization，不创建登录会话。

|字段|类型与校验|
|---|---|
|`loginId`|string；trim后4～32位；`[A-Za-z][A-Za-z0-9_]{3,31}`；按现有登录服务同一规则判重，必须覆盖已导入账号，不能仅依靠前端查询|
|`password`|string；8～64个UTF-16 code unit；不trim，首尾空格也是密码；确认密码仅客户端核对，不发送|
|`displayName`|string；trim后1～24个UTF-16 code unit；教师应填写可核验姓名|
|`schoolId`|string；必须来自当前允许注册的学校，不因自选学校而自动通过学校身份核验|
|`requestedRole`|`STUDENT`或`TEACHER`；表示申请类型，不能直接作为权限集合落库|
|`teacherApplication`|仅TEACHER必填；trim后5～500字核验说明，例如院系、工号、可供学校核验的信息；STUDENT请求省略|

学生请求示例（仅字段示意，不是测试账号）：

```json
{
  "loginId": "example_user",
  "password": "example-password-123",
  "displayName": "示例同学",
  "schoolId": "school_example",
  "requestedRole": "STUDENT"
}
```

教师请求在上述字段中使用 `requestedRole=TEACHER` 并增加 `teacherApplication`。客户端没有教师权限或管理员权限勾选项；拒绝 `roles`、`capabilities`、`identityStatus`、`reviewedBy` 等未知/只读字段，返回422 `FIELD_NOT_ALLOWED`。

成功HTTP200、`code=OK`，`data`固定为：

```json
{"id":"registration_example","requestedRole":"STUDENT","status":"ACTIVE"}
```

教师成功回执：

```json
{"id":"registration_teacher_example","requestedRole":"TEACHER","status":"PENDING_REVIEW"}
```

响应不包含密码、教师核验原文、accessToken或refreshToken。客户端核对回执后清空密码，提示返回登录；不调用 `/me` 或自动授予身份。注册成功不等同已加入任何课程或小组。

### 幂等、并发与存储

- 同一幂等键与同一正文返回同一注册回执，不能创建多个账号/审核记录；不同正文复用同一键返回409 `IDEMPOTENCY_KEY_REUSED`。
- 数据库对账号规范化值建立唯一约束，两个并发注册只有一个成功；重复账号返回409 `ACCOUNT_EXISTS`。账号规范化规则与登录查找一致，客户端不静默改变账号大小写。
- 不保存含password的原始JSON或明文请求日志。沿用成熟密码哈希库；幂等存储只记录服务端安全指纹和不含敏感内容的回执，不把密码塞进幂等原文表。
- 按账号/IP限制注册频率；超限返回429 `RATE_LIMITED`，可返回 `Retry-After`。服务器关闭注册时返回403 `REGISTRATION_DISABLED`。
- 网络结果不确定时允许客户端以原正文/原键重试；客户端不持久化密码和确认密码，重建后需要重新输入。

### 教师审核与登录

- 教师申请只生成待审记录；审核前不得获得TEACHER、HELP_CONTENT_WRITE、SUPPORT_HANDLE或任何班级授权。
- 服务端以已有受控运维身份/工具核验申请人，审核动作记录审核人、时间、理由与版本，拒绝申请人自审。核验说明本身不构成教师身份的可信证据。
- 审核通过后原子激活账号并授予基础TEACHER身份；任课关系仍走已有教师认领和学校事实核验，不自动成为任意课程教师。
- 审核前，只有在正确校验账号密码后，登录返回403 `ACCOUNT_PENDING_REVIEW`；驳回返回403 `ACCOUNT_REJECTED`；错误口令仍按现有 `INVALID_CREDENTIALS` 处理。审核通过后按原会话接口登录。
- 注册幂等重放返回最初的提交回执，不将它作为审核状态查询或授权证据；实际能否登录由当前审核状态决定。本轮没有新增App审核后台或公开审核进度查询接口。

## 4. 学生代建作业编辑

### 4.1 作业列表/详情投影

以下现有响应在原字段外增加：

- `GET /squares/{squareId}/assignments` 的每项。
- `GET /assignments/{assignmentId}`。
- 创建与编辑成功的作业响应。

|字段|含义|
|---|---|
|`createdBy`|可信会话确定的实际创建者ID，不能由客户端填写；旧记录若无法确定，返回null，不能猜测|
|`canEdit`|boolean，基于当前请求人/状态投影；仅当前代建本人、origin=STUDENT、confirmationStatus=PENDING_CONFIRMATION时可为true|

教师已确认、非本人、历史或无权投影返回 `canEdit=false`。前端保持只读，不能用“待确认”标签推断所有学生都能编辑。缺少资格字段的旧服务也显示明确的只读原因。

### 4.2 编辑接口

`PATCH /assignments/{assignmentId}`，登录、幂等键必填。

```json
{
  "expectedRevision": 1,
  "name": "修正后的作业名称",
  "requirements": "修正后的任务书要求",
  "hardDueAt": "2026-12-30T15:59:59Z",
  "minMembers": 2,
  "maxMembers": 5
}
```

- 本版提交上述全部可编辑字段；`name` trim后1～100字，`requirements` trim后1～10000字，人数为整数且 `1≤min≤max≤20`；截止为有效RFC3339时间，按真实瞬间处理。
- 先在服务端核验创建者、当前课程读取资格、待确认状态与原revision，再执行更新。只读 `id/squareId/createdBy/origin/confirmationStatus/gradingEnabled/sourceReferences` 不允许回写。
- **已有任意小组使用此作业时，只允许修正名称/任务书文字，不允许此接口直接修改截止和人数约束**；涉及约束变化返回409 `ASSIGNMENT_IN_USE`。本轮不迁移任务、不修改成员、不改已有成绩，也不把作业改到另一个广场。
- 无项目时可修改这些约束；仍不得把待确认作业自动确认或启用评分。旧来源引用保持。
- 成功返回同一完整作业对象，revision递增；客户端核对ID、课程、原创建者、状态与保存内容后才提示成功。
- 教师确认和学生编辑必须对同一revision竞争，只有一个先成功；另一个409 `RESOURCE_CHANGED` 或 `ASSIGNMENT_LOCKED`，不能在教师确认后追加学生写入。
- 幂等重放也重新检查当前资格/状态。若已经确认或后来又有修订，不回放旧可编辑权限/旧版本成功对象；明确返回当前冲突，客户端保留输入供本人核对。

## 5. 友好的字段错误

成功包络不变。校验失败可按以下结构补充，兼容原来的 `data=null`：

```json
{
  "code": "VALIDATION_FAILED",
  "message": "请检查填写内容",
  "data": {
    "fieldErrors": [{"field":"weeklyHours","code":"OUT_OF_RANGE","message":"每周投入时间需为0至60小时"}]
  }
}
```

`fieldErrors` 最多20项，字段为 `field/code/message`，**不要返回填写值**，尤其不要回显password或教师核验材料。建议字段错误码：REQUIRED、INVALID_FORMAT、TOO_LONG、OUT_OF_RANGE、DUPLICATE。客户端主提示使用中文字段标签，不展示协议字段名和长请求编号；主动打开“问题详情”后才展示技术原因与请求编号。客户端本地校验产生的状态值标为“应用状态”，不能将其当作原始HTTP响应。继续返回 `X-Request-Id` 便于排查。

## 6. 现有接口实际差异，需一并核对

### 6.1 本人协作偏好原值保存也被拒绝

本轮用独立演示账号读取 `/me/profile` 后，按当前App字段原值PUT，`expectedRevision=0`，返回422 `VALIDATION_FAILED`、`data=null`。

请求编号：`p61-a8c9f3a1-2bdf-4836-844e-68b3cb2007d4`。这是P62实际复核请求编号，探针复用了先前编号前缀。

字段为 `expectedRevision/displayName/skills/weeklyHours/availability/collaborationGoal/intro`；weeklyHours是整数，密码不涉及本请求。服务器未给出具体字段原因，因此**尚不能认定只改某一个字段即可修复**。请根据日志确认DTO与首次版本0规则；允许尚无本人记录时用expectedRevision0原子创建，后续按实际版本保存，返回具体fieldErrors，不要要求客户端伪造revision1。

客户端已补昵称1～24字、技能最多8项/每项20字、每周0～60整数、协作时间/期待180字、简介300字的本地校验；服务器继续执行对应校验。

### 6.2 通知偏好仍返回旧结构

本轮真实响应（不含任何账号凭据）：

```json
{"revision":0,"channel":"IN_APP","chatDefault":"MENTIONS","quietStart":"22:00","quietEnd":"08:00","timezone":"Asia/Shanghai"}
```

当前App需要下列完整结构：

```json
{
  "revision": 0,
  "timezone": "Asia/Shanghai",
  "quietHours": {"enabled":true,"start":"22:00","end":"08:00"},
  "courseNotices":"IN_APP",
  "mentions":"IN_APP",
  "supportReplies":"IN_APP",
  "chatDefault":"MENTIONS",
  "projectChatModes":[]
}
```

P62明确允许尚未保存的私人偏好revision0；首次PUT用expectedRevision0，保存后返回真实正整数revision。`channel/quietStart/quietEnd`不能替代三个提醒渠道和quietHours对象；客户端不会默认为所有渠道静音或编造已保存版本。

## 7. 联调验收清单

1. 匿名加载注册选项；关闭开关/空学校/未部署时清楚提示且不能提交；不发送旧Bearer或自动刷新。
2. 学生注册→返回登录→正常登录；校验错误定位字段；重复账号/并发注册不能创建多份。
3. 教师注册→待审→正确口令登录提示待审；审核前无教师能力；受控审核后登录并按既有规则认领课程。
4. 注册请求超时后原键重试只返回同一回执；密码及确认密码不进入日志、分发包或客户端恢复状态。
5. 代建本人编辑名称/要求后同ID读回；非本人403，教师已确认后不能修改；两设备版本竞争不能覆盖。
6. 已有小组的作业修改人数/截止被拒绝，文字修正仍可；原成员、任务、课程、确认与成绩均保持正确。
7. `/me/profile` 首次0版保存及后续版本冲突；完整通知偏好0版读取/首次保存/再次保存。
8. API37及队友实际手机验证键盘上方可见当前输入框、末尾可滚动至保存；错误弹窗显示中文下一步，详情才出现技术信息。

客户端的单元/模拟器夹具只能证明客户端按本契约处理；真实注册、审核、编辑保存需服务器部署后单独验收，记录最终版本与请求编号。

键盘处理依据：[Android Views键盘与WindowInsets说明](https://developer.android.com/develop/ui/views/layout/sw-keyboard)。本轮沿用adjustResize，并处理IME inset；不依赖它独自避让键盘。

## 8. 续做补充：合并资料、横屏输入与限流

1.0.3尚未分发，本次把旧1.0.2残留问题合入同一版本，未更换签名、服务器或权限。

### 8.1 双边广场详情

- 原接口 `GET /square-merge-proposals/{id}` 的文档字段为 `sides[].agreeCount/requiredCount`；客户端现兼容这些字段和旧演示的 `agree/requiredYes`。两套同时返回必须一致，门槛按冻结人数严格过半核对，不能把缺字段显示为0。
- 必须有两侧不同的squareId并分别对应sourceSquareId/targetSquareId；eligibleCount与票数必须为合法整数。反对、弃权、未投明细未返回时明确说明未提供，不补假0；提供明细时须三项齐全且总数吻合。
- 资料卡新增明确入口，分别读取原有 `GET /squares/{squareId}`。提案没有嵌套完整square时按ID读取课程资料，不再显示空白课程名；查看资料不改变迁出/保留方向、不投票、不执行合并。
- 如允许本人投票，服务端需明确返回该侧 `canVote:true` 和 `myBallot`。首次无选票用空对象或revision0；已投票返回实际choice与正整数revision。客户端不从全局角色、计票总数或空选票反推资格。缺资格字段时仍可查看资料，并说明暂不能投票。
- PUT `/square-merge-proposals/{id}/me/ballots` 沿用squareId/expectedRevision/choice；点击选票先确认，再提交。本轮不对真实课程提交选票或执行合并。

### 8.2 横屏输入法

共用输入框保留 `EditorInfo.IME_FLAG_NO_FULLSCREEN`，变更下一项/完成/搜索动作时保留该标志；继续保留IME避让与焦点滚动。这样向输入法请求在横屏保留App，而非进入整屏提取编辑器。依据：[Android EditorInfo官方说明](https://developer.android.com/reference/android/view/inputmethod/EditorInfo#IME_FLAG_NO_FULLSCREEN)。Android11真机已确认横屏保留App、未进入整屏提取编辑器；密码自动使用系统安全键盘且焦点位于App可见区。当前讯飞显示为居中悬浮面板，仍遮住页面中部，不能宣称任何输入法均完全无遮挡；用户可自行移动面板或切回固定键盘，本次没有更改用户输入法设置。完整验证范围以verification-p62.json为准。

### 8.3 登录限流

429主提示为“登录尝试暂时受限”，保留填写内容，说明先核对账号密码、不要连续点击。服务器若返回合法 `Retry-After`（秒数或HTTP日期），客户端显示约需等待的秒数/分钟；缺失或无效时只说稍后重试，不编造固定等待时间。未添加自动重试或绕过限流。错误代码、原始原因与请求编号仍只在主动详情中出现。

### 8.4 本次续做的联调范围

先前的真实API结果保持为历史证据。本次电脑访问同一服务器时TLS握手超时，不能据此宣称服务器全局不可用；授权Android11真机的一次匿名GET /health也未能连接443（ConnectException），结果独立记录。注册、教师审核及作业编辑是否已部署，仍需成功的真实请求证明。独立测试包的回归与模拟器夹具均不能替代真实后端验收。
