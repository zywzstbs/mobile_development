# 咕噜派后端联调接入

日期：2026-11-03。后端版本 `0.1.0-P16`，环境 `demo`，数据库迁移已到 `V028`。下面这台机器就是联调环境，前端直接连它。

这份说明里的口令只给这次局域网演示用。不要提交到仓库，不要发到公开群。

## 1. 地址

| 用途 | 值 |
|---|---|
| 基址 | `http://192.168.5.12` |
| 接口前缀 | `/api/v1` |
| 健康检查 | `GET http://192.168.5.12/health` |
| 协议 | 只使用 HTTP。这台机器没有域名，443 没有证书 |

客户端如果自己拼接 `/api/v1`，基址只填 `http://192.168.5.12`。基址里已经带了 `/api/v1` 时，不要再拼一次。

健康检查不需要登录。当前返回类似：

```json
{"code":"OK","message":"成功","data":{"status":"UP","database":"UP","environment":"demo","version":"0.1.0-P16","time":"2026-11-03T09:39:35Z"}}
```

`status` 和 `database` 都是 `UP` 才算后端可用。

## 2. 请求约定

成功和失败都是这个信封。失败时 `data` 为 `null`。业务是否成功看 HTTP 状态和 `code`，不要只看 body 里有没有 JSON。

```json
{"code":"OK","message":"成功","data":{}}
```

- `Content-Type` 使用 `application/json`。字段必须是 JSON 字符串，不要把学号、版本号写成数字。
- 未知字段返回 `422`，`code` 为 `FIELD_NOT_ALLOWED`。按接口文档发字段，不要把本地模型整包塞回去。
- 时间是 UTC、秒精度：`2026-11-03T09:39:35Z`。点数用十进制字符串，例如 `"6.00"`。
- 校验失败通常只有一句「字段校验未通过」或「请求格式无效」，响应里没有字段名。联调时保留完整请求体。
- 缺必填查询参数也返回 `400` / `MALFORMED_JSON`，文案是「请求格式无效」。
- 可选请求头 `X-Request-Id`：1～64 位字母、数字、`.`、`_`、`:`、`-`。服务端会在响应头原样带回；不传则由服务端生成。排错时把这个值一起发过来。
- 业务 JSON 上限 1MiB。不要跟随重定向。
- 浏览器页面如果和 `http://192.168.5.12` 不同源，请求会被浏览器拦住。当前服务没有 CORS。Android 原生请求不受这个限制。

登录后除健康检查、登录、刷新、公开帮助读取、文件字节地址以外，都带：

```http
Authorization: Bearer <accessToken>
```

`tokenType` 固定是 `Bearer`，后面有一个空格。access 有效期 30 分钟，登录响应里的 `expiresIn` 单位是秒，当前为 `1800`。refresh 固定 7 天，过期时间在 `refreshExpiresAt`。

刷新：

```http
POST /api/v1/auth/sessions/refresh
```

```json
{"refreshToken":"<refreshToken>"}
```

收到 `401` / `SESSION_EXPIRED` 时，用原 refreshToken 刷新一次，再用新的 accessToken 重试刚才的请求。刷新失败就回到登录页。不要在每次请求前都登录。

会改数据的接口需要请求头 `Idempotency-Key`：1～128 个可打印 ASCII 字符。同一个人、同一个接口、同一把钥匙、同一份正文，重复提交会得到原来的结果。同一把钥匙配了不同正文，返回 `409` / `IDEMPOTENCY_KEY_REUSED`。超时后重试必须沿用原来的钥匙，不要自动换一把新的。登录和刷新不需要这个头。

## 3. 登录

```http
POST /api/v1/auth/sessions
Content-Type: application/json
```

```json
{"loginId":"student_full_01","password":"<见下表>","deviceLabel":"联调机"}
```

`deviceLabel` 可以省略。成功时 `data` 里有 `accessToken`、`refreshToken`、`tokenType`、`expiresIn`、`refreshExpiresAt` 和 `user`。

`user` 字段：`id`、`displayName`、`schoolId`、`identityStatus`、`roles`、`skills`、`revision`、`capabilities`。没有能力时 `capabilities` 是空数组。权限以服务端当次判断为准，客户端只拿它决定入口显不显示。

当前用户：

```http
GET /api/v1/me
Authorization: Bearer <accessToken>
```

注销：

```http
DELETE /api/v1/auth/sessions/current
Authorization: Bearer <accessToken>
Idempotency-Key: <本次注销专用钥匙>
```

连续 5 次密码错误会锁定约 15 分钟，返回 `429` / `RATE_LIMITED`。

已用 `student_full_01` 从局域网登录，并读到了广场列表和「演示快速组」。

## 6. 文件

上传分三步。业务接口走 Bearer；传字节的那个地址不要带 Bearer。

1. `POST /api/v1/files/upload-intents`，带 `Authorization` 和 `Idempotency-Key`。
2. 按返回的 `upload.method`、`upload.url`、`upload.headers` 发原始字节。方法是 `PUT`，地址在 `http://192.168.5.12/internal-file-transfer/<token>`。请求头带返回的 `Content-Type`，不要带 `Authorization`。上传授权大约 10 分钟。
3. `POST /api/v1/files/{fileId}/completions`，带 Bearer、`Idempotency-Key`，正文包含 `expectedRevision` 和 `uploadToken`。状态变成 `READY` 之后，业务接口才能引用这个 `fileId`。

下载先 `POST /api/v1/files/{fileId}/download-authorizations`，再按返回的地址 `GET` 字节。这个 GET 也不带 Bearer。下载授权大约 5 分钟，过期就重新申请。

`purpose` 只允许：

| purpose | 约束 |
|---|---|
| `DELIVERY_ARTIFACT` | 必须带当前项目 `projectId`，调用者是项目成员 |
| `WORK_ARTIFACT` | 不能带事项或工单 ID |
| `SUPPORT_ATTACHMENT` | 只能是图片，不能带项目或事项 ID |
| `MATERIAL_PROOF` | 当前直接 `403`。人员证明先不要走这条上传 |

允许的 `contentType`：`image/png`、`image/jpeg`、`image/webp`、`application/pdf`、`text/plain`、`text/markdown`、`application/vnd.openxmlformats-officedocument.wordprocessingml.document`。扩展名要和类型一致，文件内容也要真是这种格式。单文件最大 8MiB。`sha256` 若填写，用 64 位小写十六进制。

本机 `content://` 路径不能当作服务端文件。P50 客户端现有附件入口仍是本机存储；要在 App 里上传，需要补「申请意图 → PUT 字节 → 完成确认 → 保存 fileId」。

## 7. Android 侧

目标机器是局域网 IP 上的明文 HTTP。Android 9 及以上默认禁止明文流量，需要在网络安全配置里允许 `192.168.5.12`，或者在调试包打开 cleartext。正式包上线到有证书的域名后再关掉。

建议沿用现有客户端的超时：连接 15 秒，读取 25 秒。聊天列表不要假设一次就能拉完；历史消息超过一页，变更要带已有的变更游标继续拉。

帮助文章目前有一条「如何提交任务」。它的入口类型是 `TASK`。如果当前客户端只认识 `NONE`、`CONNECTION`、`COURSE`、`PROJECTS`、`APPLICATIONS`、`GRADES`、`NOTIFICATIONS`、`SUPPORT`，这条文章可以读到，跳转入口对不上是预期情况。帮助内容维护入口看 `capabilities` 里的 `HELP_CONTENT_WRITE`，有效账号是 `operator_full_01`。

## 8. 联调时常见返回

| HTTP | code | 含义 |
|---|---|---|
| 200 | `OK` | 成功 |
| 400 | `MALFORMED_JSON` | JSON 坏了，或少了必填查询参数/请求头 |
| 400 | `IDEMPOTENCY_KEY_REQUIRED` | 这次写入没带合法幂等键 |
| 401 | `INVALID_CREDENTIALS` | 登录名或密码错误 |
| 401 | `SESSION_EXPIRED` | access 失效，先刷新 |
| 403 | `FORBIDDEN` | 登录有效，但这个人不能做这件事 |
| 404 | `NOT_FOUND` | 资源不存在，或调用者不该知道它存在 |
| 409 | `RESOURCE_CHANGED` | 版本旧了，重新 GET 后再提交 |
| 409 | `IDEMPOTENCY_KEY_REUSED` | 同一把幂等键被拿去提交了另一份内容 |
| 413 | `PAYLOAD_TOO_LARGE` / `FILE_TOO_LARGE` | 正文或文件过大 |
| 422 | `FIELD_NOT_ALLOWED` | 多传了接口不认识的字段 |
| 422 | `VALIDATION_FAILED` | 字段内容不合法 |
| 429 | `RATE_LIMITED` | 登录等操作太频繁 |
| 503 | `SUPPORT_ROUTE_UNAVAILABLE` | 求助没有可用受理路由。当前演示路由已经配好 |

接口路径和字段以 `docs/修改/咕噜派_API接口设计文档_P58_完整重编版.md` 为准，冲突处以 `docs/backend/01-决策与契约补充.md` 版本 1.1 为准。
