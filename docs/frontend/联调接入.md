## 2. Android 网络配置

Android 清单声明网络权限：

```xml
<uses-permission android:name="android.permission.INTERNET" />
```

Retrofit 配置示例，沿用客户端已有 OkHttp 和 JSON converter：

```kotlin
Retrofit.Builder()
    .baseUrl("https://124.220.167.12/api/v1/")
    .client(okHttpClient)
    .addConverterFactory(jsonConverterFactory)
    .build()

// 相对路径不要以 / 开头，否则 Retrofit 会丢掉 baseUrl 中的 /api/v1。
@POST("auth/sessions")
suspend fun login(@Body body: LoginRequest): ApiEnvelope<SessionView>
```

此环境不需要允许 cleartext。若客户端有自定义网络安全配置，确保允许系统 CA，移除跳过证书或主机校验的代码。可先使用连接超时 15 秒、读取超时 25 秒，再按网络情况调整。[Android 网络安全配置](https://developer.android.com/privacy-and-security/security-config)。

模拟器和真机都直接连接上述公网地址，不使用 `10.0.2.2` 或旧局域网 IP。将 origin 和 API baseUrl 放在统一环境配置中，避免页面自行硬编码地址。

令牌放在应用私有存储中，并使用 [Android Keystore](https://developer.android.com/privacy-and-security/keystore) 保护用于加密持久化令牌的密钥；不放到外部存储，不写入崩溃上报或备份文件。会话日志仅保留脱敏元信息；即使隐藏了 Authorization 请求头，BODY 级日志仍可能泄露登录密码和刷新令牌。

OkHttp 鉴权拦截器只给此服务 origin 下的 `/api/v1/` 业务请求附加 Bearer，排除登录、刷新、注册选项及注册提交。文件字节传输使用独立的无鉴权拦截器客户端；其 URL 本身是短期授权凭证。刷新通过独立请求或重试标记绕开同一刷新逻辑，防止 Authenticator 递归。

## 3. JSON、类型与请求头

业务成功/失败使用统一信封：

```json
{"code":"OK","message":"成功","data":{}}
```

业务失败时通常 `data: null`；字段校验错误可能返回 `data.fieldErrors` 数组，每项为 `field/code/message`，客户端应将其显示到对应输入项。同时检查 HTTP 状态与 `code`；网络错误、代理拒绝或超大请求可能没有此 JSON 信封。

| 内容 | 约定 |
|---|---|
| JSON 请求 | `Content-Type: application/json` |
| 业务鉴权 | `Authorization: Bearer <accessToken>` |
| 写操作 | 按接口要求带 `Idempotency-Key`，推荐每次逻辑操作生成 UUID |
| 排障标识 | 可带 `X-Request-Id`，读取响应头中的最终值 |
| ID、学号、令牌、游标 | JSON 字符串；ID 和游标作为不透明值处理 |
| `revision`、`expectedRevision`、`sizeBytes`、`expiresIn` | JSON 整数，例如 `"expectedRevision": 1` |
| 点数/十进制业务值 | 按接口使用字符串，例如 `"6.00"` |
| 时间 | UTC ISO 8601、秒精度，例如 `2026-11-03T13:15:52Z`，客户端转本地时区 |

未知字段会被拒绝，数字不会自动转换成字符串。只发接口定义的 DTO 字段，不把本地完整模型原样提交。JSON 正文上限 1MiB，响应上限 2MiB，集合上限 1.75MiB；文件走独立字节接口。

`X-Request-Id` 为 1～64 位字母、数字、`.`、`_`、`:`、`-`；缺失或不合法时服务端生成。日志中不记录密码、Bearer、refreshToken、uploadToken 或文件授权 URL。

## 4. 登录、刷新与注销

登录无需 Bearer 或幂等键：

```http
POST /api/v1/auth/sessions
Content-Type: application/json
```

```json
{"loginId":"<已导入的登录名>","password":"<单独交付的密码>","deviceLabel":"Android 联调机"}
```

`deviceLabel` 可省略。成功时 `data` 包含：

| 字段 | 类型/意义 |
|---|---|
| `accessToken` | 不透明字符串，不按 JWT 解码 |
| `refreshToken` | 刷新令牌，按平台安全存储能力保存 |
| `tokenType` | `Bearer` |
| `expiresIn` | 整数秒，当前为 1800 |
| `refreshExpiresAt` | refresh 固定 7 天有效期的绝对时间 |
| `user` | `id`、`displayName`、`schoolId`、`identityStatus`、`roles`、`skills`、整数 `revision`、`capabilities` |

当前用户：`GET /api/v1/me`。除健康检查、登录、刷新、注册选项、注册提交、公开帮助读取及短期授权文件字节地址外，业务请求带 Bearer。公开帮助读取是 API 前缀下的 `GET /help/content-pack`、`GET /help/articles`、`GET /help/articles/{id}`；内容可见范围仍按业务规则判断。

刷新无需 Bearer 或幂等键：

```http
POST /api/v1/auth/sessions/refresh
Content-Type: application/json
```

```json
{"refreshToken":"<refreshToken>"}
```

收到 `401 / SESSION_EXPIRED` 时合并并发刷新为一次请求，保存返回的完整会话结果，用新 accessToken 重试原请求一次。写操作保留原幂等键和正文。当前刷新返回同一个 refreshToken，**不会延长其固定到期时间**。刷新失败或过期就清理本地会话并回登录页，不无限递归刷新。登录失败的 `INVALID_CREDENTIALS` 不进入刷新流程。

注销带 Bearer 和幂等键，正文可省略：

```http
DELETE /api/v1/auth/sessions/current
Authorization: Bearer <accessToken>
Idempotency-Key: <本次注销 UUID>
```

登录失败窗口为 15 分钟，累计 5 次失败后封锁约 15 分钟；命中后返回 429 和 `Retry-After`。当前反代下的来源 IP 识别仍待加固，客户端不要自动循环尝试密码。

## 5. 幂等、版本与分页

幂等键为 1～128 个可打印 ASCII 字符。登录、刷新不需要；其他写操作按具体接口携带。同一用户、方法、路径、键和等价正文代表同一次操作。断网或超时重试沿用原键，新操作生成新键；不同正文复用原键返回 `409 / IDEMPOTENCY_KEY_REUSED`。回放仍检查当前权限，撤回或已变化资源可能按当前状态投影，不保证永远逐字一致。

要求 `expectedRevision` 的接口，先读取资源，再提交返回的整数版本。遇到 `RESOURCE_CHANGED` 等冲突时重读并让用户确认，不只更新版本号后自动覆盖。

常见列表在 `data` 中使用：

```json
{"items":[],"nextCursor":null,"hasMore":false,"total":0}
```

按 `hasMore`、`nextCursor` 翻页，不解析游标。聊天等接口有专用游标字段，以对应接口为准。聊天使用 HTTP 列表/变更接口同步，不把当前地址当作 WebSocket 地址。遇到 `CURSOR_EXPIRED` / `CHAT_SYNC_EXPIRED`，重建相应列表/同步状态。

## 6. 文件上传与下载

业务授权接口带 Bearer、幂等键和 JSON。字节 URL 使用独立客户端，不自动附加 Bearer，不拼 `/api/v1`，不按 JSON 解包。

1. `POST /api/v1/files/upload-intents` 创建意图：

   ```json
   {"purpose":"WORK_ARTIFACT","fileName":"notes.txt","contentType":"text/plain","sizeBytes":5}
   ```

   `sizeBytes` 是真实字节数。可选 `sha256` 为 64 位小写十六进制。项目交付用 `DELIVERY_ARTIFACT` 并带有权限的 `projectId`；求助附件 `SUPPORT_ATTACHMENT` 只允许图片。`MATERIAL_PROOF` 当前返回 403。

2. 保存 `data.file.id`、`data.file.revision`、`data.uploadToken`；按 `data.upload.method`、`data.upload.url` 和 `data.upload.headers` 上传原始字节。

   当前方法为 PUT，成功为 **204，无响应正文**。不使用 multipart 或 Base64 JSON。上传授权约 10 分钟。URL 应为此服务 origin 下的 HTTPS 地址，不向异常主机发送文件或业务凭证。

3. `POST /api/v1/files/{fileId}/completions` 完成确认，使用独立幂等键：

   ```json
   {"expectedRevision":1,"uploadToken":"<步骤1返回值>"}
   ```

   版本取实际返回值；只有状态 `READY` 后，业务对象才能引用 `fileId`。

下载先 `POST /api/v1/files/{fileId}/download-authorizations`，带 Bearer、独立幂等键和 JSON 正文 `{}`；再 GET 返回的 `data.url`，不带 Bearer，读取原始字节。下载授权约 5 分钟，过期后重新申请。授权 URL 是临时凭证，不写进聊天、日志或永久存储。

单文件最大 8MiB。允许 PNG/JPEG/WebP、PDF、纯文本、Markdown、DOCX；扩展名、Content-Type 和真实内容须匹配。Android `content://` 是本地 URI，需要读取内容再上传，不能当作后端远程文件地址。

## 7. 联调顺序与 curl

无需账号即可验证连通性，保持证书验证，不加 `-k`：

```bash
curl --fail-with-body https://124.220.167.12/health
curl -i https://124.220.167.12/api/v1/me
```

第二条预期为 401 / `SESSION_EXPIRED`，表示鉴权正常。

使用已生成的测试账号按第 4 节登录，再依次读取：

| 顺序 | 方法与路径（相对 `/api/v1`） | 用途 |
|---|---|---|
| 1 | `GET /me` | 当前用户、能力和 `schoolId` |
| 2 | `GET /schools/{schoolId}/terms` | 真实学期 ID |
| 3 | `GET /squares?schoolId=...&termId=...` | 当前授权广场 |
| 4 | `GET /me/projects` | 项目入口，不写死项目 ID |
| 5 | `GET /me/dashboard`、`GET /me/todos` | 首页及待办 |
| 6 | 文件三步上传、一个带版本的写操作 | 验证字节客户端、幂等和冲突处理 |

`capabilities` 用于入口展示，最终权限由服务端判断。没有课程/项目或受理路由时，空列表或渠道不可用可能是数据尚未初始化，不代表网络错误。

## 8. 常见错误与问题反馈

| HTTP / code | 处理 |
|---|---|
| 400 / `MALFORMED_JSON` | 检查 JSON 类型、必填参数与请求头 |
| 400 / `IDEMPOTENCY_KEY_REQUIRED` | 为本次逻辑操作设置合法幂等键 |
| 401 / `INVALID_CREDENTIALS` | 确认账号已导入当前环境，检查登录信息 |
| 401 / `SESSION_EXPIRED` | 刷新一次或重新登录 |
| 403 / `FORBIDDEN`、`ACCOUNT_DISABLED` | 权限/账号问题，不自动刷新重试 |
| 404 / `NOT_FOUND` | 资源不存在或不可见 |
| 409 / `RESOURCE_CHANGED`、`SOURCE_CHANGED` | 重读资源并重新确认 |
| 409 / `IDEMPOTENCY_KEY_REUSED` | 原操作与请求正文不一致，检查客户端逻辑 |
| 409 / `CURSOR_EXPIRED`、`CHAT_SYNC_EXPIRED` | 重建相应列表或同步状态 |
| 413 | 检查正文/文件/结果集大小，不无限重试 |
| 422 / `FIELD_NOT_ALLOWED` | 删除接口未定义字段 |
| 422 / `VALIDATION_FAILED` | 检查字段值、必填项及类型 |
| 429 / `RATE_LIMITED` | 按 `Retry-After` 等待，停止自动请求风暴 |
| 503 / `SUPPORT_ROUTE_UNAVAILABLE`、`REPORT_ROUTE_UNAVAILABLE` | 后端需配置受理路由，不伪造成功单号 |
| 5xx / 网络超时 | 保留排障信息；写操作沿用原幂等键重试 |

提交问题附：环境、App 版本、请求时间（带时区）、方法和路径、HTTP 状态、业务 `code/message`、响应 `X-Request-Id`、脱敏请求字段和复现步骤。去除个人信息和凭证后再分享请求/响应。

完整字段参考 [P58 API 完整文档](../修改/咕噜派_API接口设计文档_P58_完整重编版.md)、[决策与契约补充](../backend/01-决策与契约补充.md)及当前 DTO。运维操作见 [部署说明](../../deploy/README.md)。公网 HTTPS 已验证全部21个账号登录、主要场景读取、刷新、文件下载及跨课程拒绝；尚未执行 Android 真机 UI 验证。

## 9. P62 学生注册与教师申请

匿名读取 `GET /api/v1/auth/registration-options`，当前返回 `enabled=true`、`teacherApplicationEnabled=true` 和演示大学 `school_demo_full`。注册相关请求不附加旧 Bearer，不进入自动刷新流程。

`POST /api/v1/auth/registrations` 带 JSON 和 `Idempotency-Key`：

```json
{"loginId":"new_student_01","password":"<8至64位密码>","displayName":"新同学","schoolId":"school_demo_full","requestedRole":"STUDENT"}
```

账号4–32位，以字母开头，后续允许字母、数字、下划线；显示名最长24个UTF-16代码单元。学生不填写 teacherApplication。教师使用 `requestedRole=TEACHER`，并填写5–500字的 `teacherApplication`。响应 `data={id,requestedRole,status}`，id是申请ID，不是登录用户ID，响应没有访问令牌。

学生状态 ACTIVE，可按正常登录接口登录；教师状态 PENDING_REVIEW，审核前登录返回403 / ACCOUNT_PENDING_REVIEW；通过后登录取得基础TEACHER角色，拒绝后返回403 / ACCOUNT_REJECTED。审核由受控服务器CLI完成，见部署文档；Android 不提交 reviewedBy 等审核身份字段。注册本身不自动加入课程或项目。

本轮另新增 `PATCH /api/v1/assignments/{id}`，使用当前整数 expectedRevision 和幂等键，详情见P62契约；编辑权限读取响应中的 canEdit，教师确认后不可继续编辑。旧作业 createdBy 为 null 时不推测创建者权限。

资料显示名上限24；通知偏好改为 quietHours.enabled、courseNotices、mentions、supportReplies、chatDefault、projectChatModes，更新完整DTO，停止提交旧channel字段。聊天发送支持可选 replyToId，回复仍使用原消息发送路径、clientMessageId与幂等键。

学生注册/登录、教师申请/审核/登录、资料和偏好已在124服务器实际验收。作业编辑与聊天回复已在同版本镜像、线上数据隔离副本中验收，未向现有课程写入验收内容；尚未完成Android真机UI验收。
