## 3. 数据库迁移 V003

新增：

- `term`：学校学期、纯日期范围、学校内 ordinal 唯一
- `period`：学校/学期节次、本地 `time`、学期内 ordinal 唯一、开始<结束
- `course_name`：学校课程名、规范名唯一、别名 JSONB
- `verified_course`：管理员核验的真实教学班；`external_key` 与 `canonical_key` 唯一；教师外键
- `verified_enrollment`：真实教学班+学生唯一；`valid` 标记核验事实
- `square`：定位对象；`canonical_key`、`square_no` 唯一；可关联 verified_course；`authorization_epoch`
- `course_membership`：square+user 唯一；`ACTIVE/LEFT/REMOVED`
- `assignment`：origin `STUDENT/TEACHER`；confirmation `PENDING_CONFIRMATION/CONFIRMED/MAPPED`；人数 CHECK；`grading_enabled`
- `preview_token`：5 分钟课程匹配 token 的摘要、用户、body_hash、payload、到期
- `square_no_seq`：稳定 `SQ-<年>-<6位序号>`

关键约束：`uq_term_school_ordinal`、`uq_period_term_ordinal`、`uq_course_name_school_normalized`、`uq_verified_course_external`、`uq_verified_course_canonical`、`uq_verified_enrollment`、`uq_square_canonical`、`uq_square_no`、`uq_course_membership`。

## 4. 实现要点

### 4.1 规范课表与匹配

- 输入 slots 先验证 weekday 1～7、periodId 属于当前学校学期、startWeek≤endWeek、CUSTOM 的周次非空且位于区间内；非 CUSTOM 的 customWeeks 必须为空。
- 规范签名包含：学校、学期、规范化课程名、教师名、展开后的 `weekday|periodId|week` 集合；对象键/数组不参与，周次去重排序。
- ALL 与列出全部周次的 CUSTOM 生成同一签名；ODD/EVEN 不同；教师或时段不同即不同签名。
- 同名但教师/时段不同的真实班不会混同。
- COURSE-10 只读匹配：返回 exactMatch、空 candidates、normalizedInput、canCreate、5 分钟 token、expiresAt；不创建广场/成员关系。
- token 只存 SHA-256 摘要，绑定用户、规范输入摘要和到期时间；COURSE-09 创建时重新规范化并核对 body_hash。

### 4.2 广场创建

- 事务内按 `canonical_key` 取 `pg_advisory_xact_lock`，再查已有广场；唯一约束兜底。
- 已存在规范广场时返回既有定位结果（canCreate 已为 false 时也由服务端决定），不重复创建。
- 若能按签名找到 `verified_course`，广场关联该真实教学班；否则为未核验定位对象（`verified_course_id=null`）。
- 当前用户若为真实教学班教师或有效核验学生，服务器建立/恢复 `course_membership ACTIVE`；不自动授予教师或班级管理权。
- `squareNo` 由数据库序列生成，稳定不复用。
- 创建广场写入 `SQUARE_CREATE` 审计。

### 4.3 作业与确认

- 只有当前真实教学班教师或有效核验学生可创建作业。
- 学生创建：origin `STUDENT`、confirmation `PENDING_CONFIRMATION`、revision 1、gradingEnabled=false。
- 教师创建：origin `TEACHER`、confirmation `CONFIRMED`、revision 1、gradingEnabled=false。
- 教师确认：必须当前教师，expectedRevision 匹配，状态 PENDING；CAS 更新 revision+1；重复确认 409 RESOURCE_CHANGED。
- 确认不设置 gradingEnabled；正式评分规则属于 P09。
- 作业来源材料 P02 只接受 `LINK`（http/https、最多10个）；FILE 引用等 P05F 文件数据面接入后再允许。
- 写接口均要求幂等键；回放时重新核账户与资源级权限。

### 4.4 CLI 学术数据导入

命令：

```bash
--app.cli.command=import-users     # 学校→用户（P01）
--app.cli.command=import-academic  # 学期→节次→课程名→真实课程→选课事实（P02）
```

- 本阶段数据依赖 P01 学校和用户；两条命令按上述顺序执行。
- `import-academic` 对一个文件先做全量校验：未知学校/学期/课程名/教师、跨校教师、教师缺 TEACHER 角色、学期/节次序号冲突、课程规范名/外部键/签名重复、未知或跨校选课用户、非法课表时段都会汇总报错；有错误整批拒绝。
- 写入使用一个事务，按学期→节次→课程名→真实课程→选课事实顺序执行。
- `--app.cli.dry-run=true` 只校验不写入。
- 同一文件 SHA-256 已存在 `ACADEMIC/APPLIED` 批次时显式复用并输出 `[reused]`，不重复写行。

## 7. 已知边界与实现说明

1. **自定义课程名**：响应 `CourseMatch.normalizedInput.courseNameId` 为 `null`（无字典 ID）。原始字段表标为 string，但请求允许 customCourseName 且匹配不得写课程字典；保留 null 以免伪造 ID。创建广场使用 custom 名称并生成未核验广场。
2. **相似候选**：`CourseMatch.candidates` 当前返回 `[]`，只提供 exactMatch。原始契约未定义 matchKind/differences 的具体枚举与算法，未编造业务；P08 广场合并前如有需要再补充。
3. **作业来源材料**：P02 只接受 `LINK`；`FILE` 在 P05F 文件 READY/引用核权就绪后接入。
4. **课程成员**：创建广场只给当前创建者（且是真实教学班教师/有效核验学生）建立 ACTIVE；其余学生需 P02B 的可信名单确认/课程码入课流程，不自动扩权。
5. **CLI**：P01 与 P02 分两条命令，依赖顺序为 users→academic；学术文件内部严格按学期→节次→课程名→真实课程→选课事实校验/写入。
6. 未实现 P02B（教师认领、授权、课程码、入课申请）、P03 及之后的接口；无 Android 联调、无云部署。
7. `preview_token`/导入批次等清理任务归 P16。
