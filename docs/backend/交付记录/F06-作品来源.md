## 2. 五项统计口径

|字段|来源|有效状态/去重|时间口径|
|---|---|---|---|
|`acceptedDeliveries`|`unit_acceptance` + `submission` + `delivery_unit` + `unit_share`|只算 `passed=true`、本人有份额、任务 `mode='ASSESSED'`；按 `unit_id` 去重|无|
|`confirmedUnits`|`contribution_confirmation`|本人 `user_id` + 正式任务；按 `unit_id` 去重|无|
|`independentReviews`|`acceptance`|`reviewer_id=本人`、`kind='INDEPENDENT'`、正式任务；排除本人对同一提交单元有份额的自验/利益冲突；按 `acceptance.id` 去重|无|
|`onTimeDeliveries`|上述有效交付项|`submission.submitted_at <=` 该 unit 的 `unit_due_snapshot_json`，缺失时回退 `due_snapshot`/`task.due_at`|提交时固定快照，不随后续 dueAt 改写|
|`lateDeliveries`|同上|`>` 上述截止快照|同上|

- 普通任务（`mode='ORDINARY'`）不进入正式分值/证据统计。
- 先按来源聚合再连接 project；使用 `count(DISTINCT ...)` 且不靠最终 DISTINCT 掩盖一对多 JOIN 放大。
- 项目候选集是三类证据的并集；仅当过成员但没有有效证据的项目**不出现**（无贡献返回空是正常结果）。
- 跨学校/无关用户无法枚举：所有子查询都以 `userId` 为参数，不外扩到他人记录。
- 排序：`project.updated_at DESC, project.id ASC`，无分页、完整 total。
