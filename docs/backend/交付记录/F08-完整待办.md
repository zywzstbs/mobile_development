## 2. 授权与输出

- 项目相关事项要求当前 `membership.status='ACTIVE'`；历史成员只保留 PEER_REVIEW 这类明确窗口内的事项。
- 教师事项（MEMBER_CHANGE、GRADE_APPEAL）用 `teacher_assignment.active` 判定，不要求项目成员身份。
- 申请人/受邀人可尚未入组，因此这两类不强制项目成员 JOIN。
- `ACTION` 只发给现在确实可执行的人；`WAITING` 只发给本人事项在等别人。不能仅凭“项目成员”把所有事项发给全员。
- 稳定 `todoId` + 来源 `revision` + 来源 `updatedAt`；排序 `updatedAt DESC, id ASC`。
- 同资源不同真实动作使用不同 action 片段；同一 ID 去重。
- 完整来源、状态、权限、退出条件、P50 入口见[待办来源矩阵](待办来源矩阵.md)。

## 3. 已实现的状态分支

|type|ACTION|WAITING|
|---|---|---|
|TASK|本人责任普通/已生效正式任务；指定验收人待验收|本人提交待验收|
|AGREEMENT|未确认的份额/统筹/验收安排|发起人等待确认|
|CHANGE_PROPOSAL|受影响人未确认|发起人等待确认|
|REVIEWER_INVITATION|受邀验收人待回应|项目负责人等待回应|
|APPLICATION|负责人处理申请|申请人等待|
|INVITATION|受邀人回应|负责人等待|
|ROLE_*|parties 中未 ack 的本人|发起人/负责人等待|
|REMOVAL_VOTE|目标人陈述、选民投票|目标人等待结果、发起人等待|
|MEMBER_CHANGE|接任人确认、转组目标回应、教师核对|发起人/负责人等待|
|MATERIAL_REQUEST|指定响应人|事项主体等待|
|PERSONNEL_HANDOFF|`to_user_id` 接受|`from_user_id` 等待|
|SQUARE_MERGE|选民投票、教师 WAIT_TEACHER 核对|发起人等待|
|PEER_REVIEW|归档后 14 天内缺失互评|无|
|GRADE_APPEAL|教师复核/待新发布|学生等待|
