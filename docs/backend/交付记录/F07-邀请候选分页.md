## 2. 分页与绑定

- 首次请求：合并 `APPLICATION` 与 `COURSE`，同 `userId` 以 `APPLICATION` 优先；按 `userId` 升序生成有序 ID 快照；`total` 为去重后的完整授权筛选结果；每页 20。
- `projectRevision` 取本次读取的项目版本，必须等于请求 `expectedProjectRevision`。
- 游标绑定：`userId` + `projectId` + `q` + `expectedProjectRevision` + `project.authorization_epoch` + 排序；15 分钟有效。
- 续页：再次校验当前成员/负责人资格与项目版本；`CursorService.resolve(..., expectedEpoch)` 实际校验 epoch；快照剩余不足 20 时 `hasMore=false`。
- 续页继承原快照到期时点，不通过不停续页无限延长同一快照。
- 若快照中的候选无法按当前授权重建，返回 `CURSOR_EXPIRED`，不静默漏页或改变 `total`。
- 展示字段（姓名、编号、技能、eligible/reasonCode）来自当前查询，不缓存整份私密响应。

## 3. 候选状态

`source` 仅 `APPLICATION`/`COURSE`。课程来源会展示不可邀请候选并标记：

|reasonCode|含义|
|---|---|
|`ALREADY_MEMBER`|已是项目成员|
|`ALREADY_RESERVED`|已有有效席位预留|
|`APPLICATION_PENDING`|已有待处理申请（同时有申请来源时以 APPLICATION 条目优先）|
|`INVITATION_PENDING`|已有待回应邀请|

这些是候选展示原因，不是公开 HTTP 错误码；`eligible=false` 时 `reasonCode` 非空，`reason` 提供中文兼容说明。
