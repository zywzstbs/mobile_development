## 2. 回放流程（实现顺序）

1. 校验登录态（`requireActiveBusinessUser`）。
2. 校验当前项目**读取资格**（ACTIVE 成员；不再在进入回放前统一 `requireWritable`）。
3. 统一幂等作用域锁 + 请求摘要比较（保持既有 `IDEMPOTENCY_KEY_REUSED` 优先级）。
4. 反序列化回执后，用稳定资源 ID 查当前数据库状态并重新投影。
5. 资源不存在或跨项目 → `NOT_FOUND`；不重新执行、不插入消息、不分配 sequence、不发 outbox。
6. 新执行才执行 `requireWritable`、内容校验和业务写入。

归档项目：保留成员身份时可回放安全投影；新发送仍 `PROJECT_READ_ONLY`。离组/封禁：回放 `FORBIDDEN`。教师/助理没有项目成员身份，不能借管理角色回放。

## 3. 动作—返回资源—可撤回/失权—回放策略核查表

检索命令：`grep -rn "idempotency.execute\|idempotencyService.execute" src/main/java`，共 86 处。按模块归并：

|模块|代表动作/返回资源|可撤回/失权|回放策略|
|---|---|---|---|
|CHAT|发送消息、撤回消息 → `Message`|正文/references/mentions 可撤回；成员会离组|**投影**：按 messageId 读当前行，撤回占位、离组拒绝、归档只读|
|BOARD|主题/回复创建、修订、撤回、状态、置顶、关注 → `Topic/Reply`|正文可撤回，历史 revision 清空|**投影**：按 topic/reply id 读当前行；读视图对 withdrawn 清正文/引用/提及|
|PROFILE|作品创建/修改/撤回 → `WorkView`|作品可撤回；仅作者本人可写|回执只回到作者本人，不跨用户泄露；本轮未加投影，保留为剩余优化项|
|GRADE|规则预览/确认、更正、结算、草稿、发布、评价/授权/撤回 → 各类成绩投影|教师可能被撤权；评价可撤回|回执只回到发起教师/学生；当前 `write()` 未重新核教师权，列为剩余问题（不影响 R01 撤回正文）|
|DELIVERY|提交/验收/撤回/份额确认/约定确认 → 提交或验收投影|提交可撤回|回执只回到同一项目成员；未投影，列为剩余问题|
|TEAM/ROLE/GOV/MERGE/TASK/NOTICE/SUPPORT/FILE/DICE|邀请、申请、岗位、人员、任务、公告、求助、文件意图、骰子等|大多不可撤回，或撤回后只影响自身可见性|默认原样回显稳定回执；仍先重新核登录态；业务读接口另行按当前状态投影|
|IDENTITY/AUTH|登录、刷新、画像 → 会话/画像|会话可撤销|登录/刷新不进幂等回执；画像回执只回本人|

结论：R01 的退出条件（聊天、留言及引用回放回归）已由 `ChatFixP13IT` 覆盖；其他可撤回资源未发现跨用户正文回放旁路，但 GRADE/DELIVERY 的重新授权与投影仍是后续审计项。
