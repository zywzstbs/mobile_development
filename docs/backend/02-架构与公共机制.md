# 架构与公共机制

## 1. 技术基线与工程结构

采用Java 21、Spring Boot 3.5.x、Maven Wrapper、Spring MVC、Spring Security、Bean Validation、Spring JDBC JdbcClient/NamedParameterJdbcTemplate、PostgreSQL 17、Flyway。JDBC便于明确锁与条件更新，不混用JPA隐式级联。JSON由Boot管理的Jackson版本处理。测试JUnit、Spring Boot Test与真实PostgreSQL（开发机Testcontainers或独立测试库），禁止用H2证明PostgreSQL锁和部分唯一索引正确。

版本不是“永远最新”承诺：初始化时锁定能解析的3.5稳定补丁及镜像digest，将Java、Maven、Boot、PG与依赖树写入构建记录。官方3.5文档确认Java21兼容：[Spring Boot系统要求](https://docs.spring.io/spring-boot/3.5/system-requirements.html)。不自行覆盖Spring/Security/Jackson各自版本。Flyway PostgreSQL模块与core同版本。

一个Maven应用，包根`cn.gulupai.server`：

```
common/{api,validation,security,idempotency,version,pagination,clock,audit}
identity/ course/ team/ role/ task/ delivery/ governance/ teaching/
report/ profile/ collaboration/ notification/ support/ file/ admin/
```

每个业务包内用api（Controller/DTO）、application（用例/事务）、domain（规则/状态）、persistence（SQL/映射）。Controller只取参数和会话、调用用例并封装；domain不依赖HttpServletRequest。模块间通过有类型的查询/命令服务调用，不调用本机HTTP。报告与教学只读授权投影，不直接暴露实体。

## 2. HTTP与类型

统一`ApiResponse<T>(code,message,data)`；成功HTTP200；错误data=null。覆盖认证失败、无权限、404、校验、JSON解析和未处理异常，避免Spring默认HTML/problem对象。创建不返回201；DELETE注销正文{}。JSON请求限制1MiB，普通响应序列化后限2MiB，完整集合限1.75MiB；错误仍输出小信封。上传字节走独立URL，不套JSON上限。

反序列化启用未知字段拒绝、禁止字符串/小数/布尔强制转换为整数；字段校验在类型解析后进行。ID不透明varchar，应用新ID用UUID随机值；不解析ID前缀。岗位/阶段编辑行的空id新增标记先按01归一化，不直接套通用非空资源ID校验；不得扩展到路径参数。金额/点数DTO为String，经正则与BigDecimal校验最多2位小数，输出规范两位字符串。以Instant存时间、UTC秒输出；合法偏移输入转Instant；学校和个人时区用ZoneId校验。Clock注入便于超时测试。

文本Java String.length计UTF-16单元；普通文本trim，密码token不trim。nullable和optional分别定义，不用Java原始int吞掉缺失值。响应{}使用专门空投影，不能对任何缺失对象都自动输出{}。

## 3. 鉴权及撤权

SecurityFilter解析Bearer，摘要查询access_token并联查session/user；用户停用、会话撤销或过期都拒绝。请求身份从Principal获取；操作作者不从正文获取。登录名全局唯一（CLI负责命名），学号在学校内唯一；角色仅作粗分流，必须再核对当前课程教师/学生关系、grant期限、capabilities、项目Membership、回避与资源关系。

受保护资源先核可知性，再决定404或403；不把私有资源不存在和失权区分返回。策略集中在Policy服务，各读取/搜索/引用/历史/文件/幂等重放共用。教师无项目聊天读取权；助理无改分权；O受理身份独立于CLASS_ADMIN。

所有更改授权的事务与业务写事务遵循03的锁顺序，事务内再次核权，避免先查有权、随后撤权但仍提交。数据库中维护authorization_epoch；广场/项目权限变化增加epoch，让游标和预览失效，不信任缓存权限。

## 4. 登录、刷新与限流

使用Spring成熟PasswordEncoder（BCrypt，成本通过目标机器测量后固定，初值10），不手写哈希。token用SecureRandom生成32随机字节base64url；只存SHA-256摘要。access30分钟，refresh7天固定期限；刷新生成新access，不延长会话也不轮换refresh。已有access在到期前可有效，注销/恢复账号统一撤销整个会话及其所有access。

登录按规范loginId摘要+可信来源IP限流，15分钟5次失败后封15分钟；成功清理相应失败计数。不存在账号也走伪哈希校验，消息一致。代理只信任内网反代，不信任任意X-Forwarded-For。

限流记录存PostgreSQL固定窗口计数，条件更新原子增加；多窗口限制一起判断。聊天2/s且30/min，主题回复10/min，定位20/min，工单5/day、举报10/day（按用户学校时区日边界计算并保存窗口起点）；429必须Retry-After。敏感登录限流日志不存原loginId和口令。

## 5. 幂等与事务模板

键作用域(userId,method,canonicalPath,key)，摘要为解析后规范JSON：对象键排序、保留数组顺序和字符串原值；不要在trim后消除原正文差异。路径是实际资源路径，不是带{参数}模板。缺键400，键长1～128可打印ASCII。

请求管线：鉴权→协议/类型校验→当前访问权→开启事务→按幂等作用域取得事务级try advisory lock→查询已提交记录→业务锁及再次核权→摘要比较/回放或执行→同事务保存业务效果、通知outbox、结果→提交→响应。拿不到幂等锁即409 OPERATION_IN_PROGRESS。进程中断时事务回滚、锁自动释放，不留下永远PROCESSING的占位。唯一约束仍是最终防线，不把哈希锁当唯一约束。

已成功结果保存resource引用、授权范围、HTTP/业务码及加密的响应投影7天。重放先重新核权，并重新投影撤回/失权字段，不能为“相同结果”泄露旧正文；ID、事件时间与已发生业务效果不变。可撤销内容不回放旧明文。响应数据加密密钥独立于数据库备份且记录key_id。登录/刷新不进入幂等响应存储。短期下载URL重放仍原URL，到期后新明确操作使用新键；不得延长已签token。写失败若未产生业务效果，不缓存临时500；同键可重试。真实FAILED文件状态等“失败且有业务效果”须明确保存该结果。

数据库异常应转换为领域码：已知约束名映射409；不可把所有unique violation都当同一冲突。事务死锁/锁超时不自动更换幂等键，不返回成功；仅在无外部副作用且事务已回滚时允许有界内部重试，否则503。

## 6. 版本、摘要与预览

revision从1单调增；UPDATE WHERE id=? AND revision=?，影响0行即冲突，不能先读后无条件写。多个来源资源必须分别核对。语义变化才增加相关版本；回复新增仅增加活动计数，不改主题正文revision。文件附件ready等变化是否影响来源由显式依赖表决定。

sourceKey/basisDigest用规范业务快照SHA-256：包括相关ID、内容版本、有效关系、约定/分项、验收/本人确认、教学更正、规则、评价草稿；不包括无关浏览时间。每种摘要有schemaVersion。预览token随机不可猜，存摘要、操作者、来源、允许动作、有效期；确认时锁来源并重建比较，任一变化整批拒绝。10分钟预览、5分钟匹配token仅证明上下文，不授身份。

## 7. 列表与聊天游标

完整列表按原文固定排序和完整total；超限413，不暗改分页。普通分页首批保存有序匹配ID快照、筛选、用户、scope/authorization epoch、15分钟期限。页内读取当前授权内容，撤回占位；若授权/筛选资格变化，409 CURSOR_EXPIRED。不得将完整正文缓存进分页快照。cursor随机token，元数据存数据库；分页总数来自首批快照。

聊天以project级序号锁分配sequence，撤回保留位置；changeSequence独立。after/before互斥，始终正序；q/around独立定位。变更游标7天，按当前messageId+revision投影，不回放已撤回原文。记录每用户已授权下发的序号区间，可合并相邻区间；阅读游标只能覆盖从原游标到目标的连续下发区间，不仅检查最大值。初始读取最新一页不能自动把更早缺口标已读。

## 8. 后台任务及可靠通知

@Scheduled仅用于触发：业务到期在请求内也核时钟，不能因任务延迟让邀请继续有效。PG job表/事务锁避免重复执行；批次100，短事务，错误指数退避并记录次数。到期邀请/预留、骰子、表决、公告、会话、游标、预览、上传、清理计划分别处理。

业务提交时同事务插入outbox，worker领取并按(sourceId,version,recipientId,category)唯一键写消息索引；提交后崩溃重跑不重复。站内消息不是推送，SYSTEM仅客户端已拉取后的本机展示偏好。待办从业务状态派生，不从outbox消费成功推断已经办理。

## 9. 文件数据面

业务URL保持FILE-01～04。后端另外实现返回URL所指的PUT/GET字节处理端点（如/internal-file-transfer/{token}，不是额外App业务接口）。10分钟上传、5分钟下载；无业务Bearer，短期token关联签发用户/用途/资源/大小并只存摘要；每次字节访问查数据库当前权限，反代不直接公开文件目录。

PUT流式写随机临时名，边读边计数/hash；超8MiB立即终止；同意图只能形成一个不可覆盖的已接收对象，重复相同字节可确认，异字节拒绝。completions在锁内核大小、签名、可选sha、用途，再原子置READY。DOCX须检查ZIP结构和OOXML标识，限制解压大小/条目数量；纯文本校验UTF-8，不伪造magic；不执行文档、不抓取普通LINK。路径只由存储key构造，用户fileName仅展示。

文件与PG无法共事务：先暂存、校验、原子rename，再提交READY；崩溃遗留由reconcile任务核对，未READY永不引用。引用添加与文件状态核查同事务；删除先进入7天清理窗口、重验引用，再删字节后标记录，失败可重试。文件READY后无引用也纳入孤立文件清理计划，避免用户反复上传耗尽磁盘。

## 10. 错误、性能与查询实现检查

错误码以原文§8及具体条目为基线（如撤回修订读取CONTENT_WITHDRAWN）；400用于协议缺失，422用于已解析但字段/业务校验无效，409用于当前来源/状态冲突，503用于真实服务/受理不可用。授权失败不返回数据库实体或具体私人事实。接口索引的通用失败验证不是要求每个GET都有revision或幂等键。

完整项目/任务列表不得N+1查询每人/每标准；先查授权ID集合，再批量查询关系并组装投影。低负载可用PG ILIKE做有权范围文字检索，转义通配符并绑定参数；不部署搜索引擎。report/sourceKey查询同一数据库快照，不能读完任务再读已变更的份额而拼出从未存在过的状态。

Jackson输出前有大小计数，超限返回小信封，不能写出一半JSON后才发现超限。下载/上传单独流式处理，文件字节不进入日志、幂等结果或JSON缓冲。请求超时小于客户端25秒读取上限，慢操作改为可核对的业务状态，不能返回伪成功掩盖仍在执行。
