## 材料提交时间可信度（U02，Android 待执行）

当前工作区没有 Android/P50 客户端源码（`../final_project/frontend` 为空），本节只列前端修改要求与契约样例，**不宣称已联调通过**。后端已按 D02 在材料详情、case 内嵌材料、本人材料列表、写响应和幂等回放统一输出：

|字段|类型|合法组合|
|---|---|---|
|`responses[].createdAt` / `response.createdAt`|string/null|`EXACT` 时真实 RFC3339 UTC；`UNKNOWN` 时显式 `null`，字段不能省略|
|`responses[].createdAtConfidence` / `response.createdAtConfidence`|string|`EXACT` 或 `UNKNOWN`|

客户端解析规则：

1. `createdAtConfidence=EXACT` 且 `createdAt` 是合法时间：按现有时区格式显示。
2. `createdAtConfidence=UNKNOWN` 且 `createdAt=null`：显示“历史提交时间不详”，不要调用 `Instant.parse(null)`、字符串截取或显示字面量 `null`/1970 年。
3. 老服务器缺少 `createdAtConfidence` 但 `createdAt` 有值：按原逻辑显示；新服务器必须遵守上面两条组合。
4. 不能因为时间未知隐藏整条 `responses[]`；正文、版本号、作者、撤回占位仍按原规则展示。
5. `canRespond/canReview/canWithdraw` 只是读取瞬间的资格提示，不是授权令牌；写接口 409 后刷新材料和 case，不自动重发制造新版本。
6. 不把未知时间当 0、当前时间或逾期依据；材料截止判断继续遵循原契约，不用不可信 legacy 时间作新的不利结论。

契约样例（材料 `data` 局部，不省略原契约其余字段）：

```json
{
  "responseVersion": 1,
  "responses": [
    {
      "version": 1,
      "authorId": "student-example",
      "content": "历史材料正文",
      "evidenceRefs": [],
      "createdAt": null,
      "createdAtConfidence": "UNKNOWN",
      "withdrawn": false
    }
  ],
  "response": {
    "version": 1,
    "authorId": "student-example",
    "content": "历史材料正文",
    "evidenceRefs": [],
    "createdAt": null,
    "createdAtConfidence": "UNKNOWN",
    "withdrawn": false
  }
}
```

联调清单：GET 材料详情、GET 人员事项内嵌材料、GET 本人材料列表、POST 回应/审核/撤回响应、同键重放各记录一次；每项核对 `createdAt` 是否为显式 null、UI 文案、正文/版本/撤回占位是否仍显示、是否崩溃或错误格式化。结果记入 08 的 F15，未执行前状态保持“待核实”。
