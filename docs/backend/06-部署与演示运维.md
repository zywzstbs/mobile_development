# 部署与演示运维

## 1. 拓扑与资源预算

单台AWS香港Ubuntu：HTTPS反向代理 → Spring Boot → PostgreSQL；Spring Boot同时处理私有文件字节流；文件和PG各自独立持久卷。Compose三个长期服务：proxy、app、db，不部署Redis、MQ、MinIO或监控全家桶。代理可用Caddy自动证书，具体镜像固定稳定版本/digest；不依赖其默认配置就宣称证书成功。

初始内存预算：app容器800MiB（JVM Xms128m/Xmx448m，预留元空间、线程、direct buffer）；PG容器450MiB（shared_buffers=96MB、work_mem=2MB、maintenance_work_mem=32MB、max_connections=30）；proxy96MiB；其余留系统和页缓存。Hikari maximumPoolSize=6、minimumIdle=1；Tomcat maxThreads=24，连接/查询超时明确设置。这里是启动预算，需要在目标机验证RSS和OOM，不是性能保证。低并发演示建议压测5～10个同时在线用户、聊天5秒轮询加文件上传。

60GB规划：系统/镜像15GB，PG8GB，附件15GB，本地备份5GB，应用日志2GB，安全余量15GB。磁盘实际以`df -h`为准，云磁盘标称GB与GiB不同；预算不是预先创建占满文件。附件15GB约能容纳1900个接近8MiB文件，考虑元数据和临时文件实际更少。全局附件占用+有效上传预留限15GiB，磁盘剩余不足安全阈值（默认8GiB）时拒绝新意图；额度在事务中预留，失败/到期释放。

达到磁盘70%提示管理员，80%暂停非必要导入，90%禁止新上传并保留小错误响应；阈值可部署配置。不得删除仍有引用/证据hold的数据腾空间。本地备份不能防整机磁盘故障，定期下载到管理员电脑。

## 2. 部署前清单

用户尚未提供真实主机和域名，以下是未来执行步骤：

1. 确认实例架构、Ubuntu版本、SSH访问、挂载卷与实际可用容量；构建对应linux/amd64或arm64镜像。
2. 买域名并解析到实例稳定公网地址，确认地址不会重启漂移；不将示例域名写入正式App配置。
3. 安全组只开放80/443给访问者，SSH限制管理员来源；不对公网开放5432或应用8080。
4. 安装Docker/Compose，建立专用运行目录与私有卷目录；应用非root运行，文件目录仅应用用户可读写。
5. 生成数据库密码、响应加密密钥、管理导入凭据等，放服务器权限受控的secret文件，不提交Git、不放镜像、不写日志。
6. 配置域名/HTTPS、代理请求体和超时；业务JSON限1MiB，文件字节限8MiB；不允许业务请求被重定向到另一主机。
7. PG只在Docker内网；健康检查通过后执行Flyway，再启动app，最后代理。
8. 实测TLS证书、续期、从Android网络访问、文件PUT/GET无业务Bearer的流程；业务端点全用HTTPS。

## 3. 配置清单

|变量|示例含义/校验|
|---|---|
|APP_ENVIRONMENT|demo或test；数据/文件/token独立|
|API_BASE_URL|真实HTTPS origin，不含重复/api/v1|
|SPRING_DATASOURCE_URL|内部db:5432数据库连接，不公开|
|DB_PASSWORD_FILE|权限受控secret文件路径|
|FILE_ROOT|持久私有目录；禁止Web静态映射|
|FILE_QUOTA_BYTES|15GiB初始预算；含上传预留|
|MIN_FREE_DISK_BYTES|8GiB初值，实际盘容量确认后调整|
|IDEMPOTENCY_ENCRYPTION_KEY_FILE|响应记录加密密钥；备份单独管理|
|TRUSTED_PROXY_CIDRS|仅Compose代理来源|
|SCHOOL/TERM目录|通过CLI导入，不硬编码示例ID|
|RECOVERY_CONTACT|真实管理联系人，不写公开密码|
|SUPPORT/REPORT路由|通过CLI配置真实演示账号，缺失对应能力503|
|HOUSEKEEPING_ENABLED|清理扫描开关；不绕过7天窗口|

域名/TLS/数据库/文件根目录是启动硬条件；支持路由按能力降级为503，可启动其他模块。教师权重必须从业务接口确认，不能环境变量生成正式默认分数。

## 4. 管理CLI设计

同应用提供`admin`非Web启动模式；CLI仅服务器受控执行，不暴露公共HTTP管理员自授接口。要求明确操作者标识及审计。以下为部署层命令规范/包装示例；实际实现的 Spring 开关按各段说明（材料恢复与核查为 `--app.cli.command=material-time-recovery[-audit]`）：

```
java -jar app.jar admin catalog-import --file catalog.json --dry-run
java -jar app.jar admin users-import --file users.csv --dry-run
java -jar app.jar admin courses-import --file courses.csv --dry-run
java -jar app.jar admin enrollments-import --file enrollments.csv --dry-run
java -jar app.jar admin import-apply --batch <batchId>
java -jar app.jar admin teacher-claim-review --claim <id> --decision APPROVE
java -jar app.jar admin account-reset --user <id>
java -jar app.jar admin routes-import --file routes.json --dry-run
java -jar app.jar admin help-import --file help.json --dry-run
java -jar app.jar admin demo-seed --scenario full
java -jar app.jar admin cleanup-plan --dry-run
java -jar app.jar admin cleanup-cancel --plan <id> --reason <text>
# W01 受控恢复历史材料提交时间：回执必须证明同材料、同版本、同作者
java -jar app.jar admin material-time-recovery --material <materialId> --response-version 1 \
  --receipt <operationReceiptId> --dry-run
# W01 只读核查已恢复行：VALID / CORRECTION_REQUIRED / UNVERIFIABLE
java -jar app.jar admin material-time-recovery-audit
```

`material-time-recovery` 只接受能精确指向 `/api/v1/material-requests/{id}/responses` 的成功 POST 回执，并要求解密结果满足：根节点材料 ID 一致、顶层 `responseVersion` 精确等于目标版本、`responses` 中该版本恰好一条且作者一致、时间为合法 Instant、可信度为 `EXACT`、未撤回；兼容对象 `response` 存在时必须与数组条目一致。恢复时间取该条目的 `createdAt`，不取 `operation_receipt.created_at`。跨版本、缺证据、坏密文、旧 keyId、已有可靠时间或异常 UNKNOWN 组合一律拒绝并保留原状态；`--dry-run` 只输出计划，不写业务数据。实际实现的 CLI 开关为 `--app.cli.command=material-time-recovery` 及 `--app.cli.material-id/--app.cli.response-version/--app.cli.receipt-id`；上文 `admin ...` 是部署层包装示例。

部署前必须先跑只读核查，不得直接批量改 `created_at`：

```bash
java -jar app.jar --spring.profiles.active=cli --app.cli.command=material-time-recovery-audit
psql "$DB_URL" -f scripts/audit-material-time-recovery.sql   # 仅只读清单/计数
```

`material-time-recovery-audit` 只扫描 `time_source='RECOVERED_EVIDENCE'`，输出 `VALID`、`CORRECTION_REQUIRED`、`UNVERIFIABLE` 三类及原因，不写库、不导出正文/密文/密钥。若出现 `CORRECTION_REQUIRED` 或 `UNVERIFIABLE`，先按既有备份流程留备份，再按 W01 第 7 节另行走受控纠错并持久化修改前审计；不得在启动迁移中自动解密全库、批量清空 EXACT 或直接覆盖 SERVER_SUBMISSION。真实/待升级库尚未核查时，状态只能是“代码修复完成、部署前数据核查待执行”。

CSV最小字段：users为loginId/schoolExternalKey/studentNo/displayName/identityRole；courses为schoolExternalKey/termExternalKey/courseExternalKey/fullName/teacherLoginId/slots；enrollments为courseExternalKey/loginId/sourceVersion。不把正式ID混进学号。目录JSON包含IANA timezone及学期日期、节次、排序；导入先解析校验全部外键，再按批事务应用，返回错误行号。dry-run生成输入摘要，apply核文件未变更。

口令不通过命令参数或普通CSV传播。新账号生成随机临时口令，只输出到权限600的私有交付文件；账号恢复先核验再重置并撤销所有会话。demo-seed的登录凭据同样另存私有文件；演示密码不写接口文档。

O账号也用既有登录，但operator_grant独立；App未提供受理界面时，可通过受控CLI调用相同应用服务处理，不能省略HELP/REPORTING接口。CLI不绕过审核、份额、评分等领域约束，只有演示场景构造器可生成声明为测试的历史阶段数据。

## 5. 演示场景包

准备1学校、1学期、2真实教学班、每班1教师、1助理、至少8学生、独立软件/举报受理账号。准备同一真实班的两个历史重复广场用于合并；不同真实班用于越权拒绝。至少两部设备/两个账号执行并发。

|场景|初始数据|现场操作|
|---|---|---|
|A基础组队|可信名单、未加入课程学生、QUICK和DETAILED项目|登录、扫码定位、确认入课、申请、邀请接受、选岗|
|B普通任务|无主TODO及依赖任务|认领、开始、上传、提交、独立验收|
|C正式计分|多份额任务及未确认约定|本人逐一接受、部分通过、重交、贡献确认、教师结算发布|
|D自检|所有当前成员参与任务且组长参与|自检理由、份额确认、账本SELF_CHECK来源|
|E人员变更|源/目标组、足够预留空间|目标邀请、教师前置、任务接任、组长LEADER项ID确认/空数组别名、最终执行/重签|
|F表决/合并|已进入投票期与即将到期两套独立数据|合法投票、资格变化、取消重发、通过后事实核对|
|G收尾|全部任务完成、复盘准备|收尾、交付预览发布、FINAL、归档；旧轮次拒绝|
|H协作|历史多页聊天、留言、公告|发送、撤回旧消息、断线补拉、知悉、催阅|
|I私人支持|真实路由与图片|求助、受理、回复、本人解决/重开、举报结论|
|J边界失败|过期码/游标、撤销grant、满岗|展示准确错误，无假成功|

演示时间数据由fixture相对Clock生成，不能把所有截止硬编码2026-10-30。生产profile禁止可调Clock、强制投骰值和fixture重置入口。现场等待48h/72h通过独立预置场景避免，不能修改正式计时规则。

## 6. 备份、恢复与清理

每日低峰备份PG和文件引用清单；文件不可变对象增量备份，备份期间暂停物理清理，确保DB快照引用的文件在复制完成前不删除。备份包含应用版本、Flyway版本、环境标识、数据库dump、文件manifest及SHA256；token/加密密钥另行加密保管。5GB本地备份预算只适合小演示数据，附件增长后必须下载异机并轮转，不能保证15GB满量附件备份仍塞进5GB。

恢复步骤：停写→备份当前状态→新隔离库restore→恢复对应文件→校验manifest→启动同版本或兼容迁移→验证登录/成绩历史/文件引用→再切换服务。恢复演练先在独立环境做，不用直接覆盖当前库测试。恢复后检查过期会话与短期token，环境密钥必须隔离。

日志轮转：JSON行不含密码/token/私密正文，按大小和天数滚动，总预算2GB；Docker logging driver也限制max-size/max-file，避免应用轮转但容器日志无限增长。定期清理旧镜像，只删未使用镜像，不删除volume。

保留计划按原文365天/180天/30天/7天/24h规则生成；每个资源先算引用/hold最大期限，再创建7天可撤销计划。即使已到执行日，也在事务中再次检查新引用、未结束复核/事项；有变化取消旧计划。删除分批、失败可重试、审计保留。未归档项目不因创建满180天被误删。

## 7. 部署验收

从外部网络登录；HTTPS业务无重定向；上传真实8MiB边界文件；应用/数据库分别重启后数据仍在；docker stats观察内存；检查5秒聊天轮询无连接池耗尽；备份恢复至少一次；磁盘不足返回可解释失败；停止worker后重启通知不重复；管理员秘密不出现在日志。确认完才填写实际部署完成记录。
