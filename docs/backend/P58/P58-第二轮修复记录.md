## R01

提问者读取本人工单不要求 `SUPPORT_HANDLE`。处理者必须同时是当前 assignee、账号未停用、持有覆盖该工单范围的有效 `SUPPORT_HANDLE`。课程工单还要是该广场当前教师，或持有未过期的 `class_grant`。助理与提问者在同一项目时返回 `RECUSAL_REQUIRED`，不自动补授权。

`SupportTicketAccess` 同时给工单详情、回复、工作台、转交候选、渠道、上传、元数据、下载授权和字节下载使用。写入发生在锁内的第二次核权之后。下载只认授权记录里的用户，并再次检查账号和工单资格，不单独相信短期 token。

## R02

`mutate` 不再因为回执里有 `transferTargetRouteId` 就在失权后返回缓存。后续重试走当前读权限；拒绝时不删除回执，也不再执行转交。首次转交仍在同一事务里用 `ticketView` 构造当次结果，不调用会要求旧处理人继续拥有详情权的投影。

## R03

`IdempotencyService` 的原路径仍用全局 `FAIL_ON_UNKNOWN_PROPERTIES`。约定回放改走 `executeHistorical`：先解密成 `JsonNode`，用回执中的 `taskId` 检查当前项目成员资格，再还原当次快照。

带 `plan`、没有顶层 `ownerId` 的旧回执，从 `plan` 提升出顶层字段。`affectedUserIds` 和 `totalPoints` 来自回执里的份额，不读取后来的约定行。找不到任务，或调用者已离组，返回 403，不把缓存正文退回去。交接续约的 id 不是约定 id 时同样先核 `taskId`。同键不同正文仍由原摘要冲突处理。

## R04

对照 P58 第 8.17 节：NOTICE-03 的 `expectedRevision` 是课程广场 revision；NOTICE-05 的 `expectedRevision` 是通知 revision。预览写入 `sourceKind=COURSE`、`sourceRevision`、发布身份、作业、标题、正文、类别、重要程度、知悉、期限和 refs。

提交时课程 revision 必须仍等于预览里的值。请求里的通知版本不能替换这个基准。标题正文相同但类别、重要程度、失效时间或发布身份与预览或当前通知不一致时拒绝。`FORMAT_ONLY` 携带预览 token 直接拒绝。`usePreview` 只在 `used_at IS NULL` 时更新，返回值必须为 1，并用 `FOR UPDATE` 锁住预览行。

契约缺口：NOTICE-03 没有公告 id，服务端不能把预览绑到某一条公告的 revision，否则就要新增必填字段。公告表也没有 refs 列，refs 只冻结在预览记录里，没有另造存储。作业范围仍允许由预览带入，这是第 8.17 节 P56 范围调整写明的。
