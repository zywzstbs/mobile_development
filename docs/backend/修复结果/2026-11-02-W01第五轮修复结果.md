## 三、K01：可信证据读取与验证

### 3.1 回执读取

`GovRepository.OperationReceiptEvidence` 扩展为：

```text
id, user_id, method, path, http_status, business_code,
result_ciphertext, key_id, created_at, expires_at
```

按回执 ID 直接读取，不调用普通幂等 execute、当前 GET 或 ReplayProjector；过期但仍存在的回执仍可读取，已删除回执明确 `NOT_FOUND`，不延长 `expires_at`、不重建回执。`created_at`/`expires_at` 仅供诊断。

### 3.2 外层验证

验证器逐项要求：目标版本存在且版本为正整数、作者明确；method=`POST`；path 精确为 `/api/v1/material-requests/{materialId}/responses`；`http_status=200` 且 `business_code=OK`；回执 userId 等于目标 authorId；密文非空；`key_id` 等于当前 `IdempotencyCipher.keyId()`。不支持的旧 keyId 明确拒绝，不做密钥猜测或轮换。

### 3.3 解密和结构验证

新增 `MaterialSubmissionEvidenceVerifier`，复用 `IdempotencyCipher` 和项目 `ObjectMapper`，以 `JsonNode` 逐项验证：

1. 根节点 `id` 等于目标 materialId。
2. 顶层 `responseVersion` 为整数且严格等于目标 version。
3. `responses` 中恰好一条目标 version；缺失、重复均拒绝。
4. 该条目 authorId 等于目标作者及回执 userId。
5. `createdAtConfidence` 明确为 `EXACT`。
6. `createdAt` 为非空合法 Instant。
7. `withdrawn` 明确为 false。
8. 若存在兼容对象 `response`，其版本、作者、时间、可信度、撤回状态必须与数组条目一致；冲突拒绝，不以兼容对象兜底。

旧格式无 `responses`、缺可信度、时间为 null/数字或其它字段类型均拒绝。未从 content、evidenceRefs、updatedAt、审核时间或回执创建时间猜测。

### 3.4 时间精度与错误

- 回执由当前 Jackson 秒级序列化，恢复只使用证据保留的秒级时间；不补造小数秒，不改全局序列化。
- 缺失目标/回执用既有 `NOT_FOUND`；参数错误用既有校验错误；证据不匹配、格式/密钥不支持用既有 `SOURCE_CHANGED`；数据库异常不被包装成“证据不足”。
- 日志/CLI 不输出解密正文、附件、密文、密钥；解析异常消息不含完整 JSON。验证结果 `VerifiedSubmissionEvidence` 为不可变 record：materialId、responseVersion、authorId、submittedAt、receiptId。

## 四、K02：接入恢复事务

处理顺序：

```text
校验参数 → 读取目标 → 读取回执 → 完整验证
→ 检查目标当前可信度/证据 → dry-run 或条件更新 → 返回结果
```

- **UNKNOWN/null**：要求 `created_at=null`、`time_source=LEGACY_UNKNOWN`、无残留恢复审计字段；dry-run 返回 `DRY_RUN` + 证据时间，不写入；正式执行条件更新为 `EXACT/RECOVERED_EVIDENCE`。
- **EXACT**：仅当 `time_source=RECOVERED_EVIDENCE`、`time_evidence` 等于同一回执引用、`created_at` 等于已验证时间时返回 `ALREADY_RECOVERED`；不更新恢复人或恢复时刻。不同证据、不同时间或 `SERVER_SUBMISSION` 一律拒绝。
- **UNKNOWN 异常组合**：时间非空、来源异常或残留恢复字段拒绝自动清洗。
- 更新条件保持 `WHERE material_id=? AND version=? AND created_at_confidence='UNKNOWN' AND created_at IS NULL`，影响行数必须为 1；0 行时重读，只有“同证据同时间”才返回 `ALREADY_RECOVERED`，否则 `SOURCE_CHANGED`。
- 提交时间来自证据；`time_recovered_at` 来自 `Clock`；保留 `legacy_recorded_at`。
- 未增加行锁，因此没有新的锁顺序；不检查材料是否已验收、事项是否已结案；不改 case/材料/作者/正文/版本/审核/权限。

已修正服务类注释中“回执时间就是真实服务器时刻”的错误描述。
