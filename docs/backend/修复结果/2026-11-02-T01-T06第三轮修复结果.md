## 二、H00：权限词汇、入口表和锁顺序

### 2.1 代码中的权限真值表

`PersonnelCaseAccessPolicy` 不再暴露含混的 `hasQualification`，改为按用途命名：

|方法|含义|关键条件|
|---|---|---|
|`isEligibleTeacher(row,userId)`|有效教师身份|账号未停用、`identity_status='VERIFIED'`、`user_role.role='TEACHER'`、账号学校=case 广场学校|
|`isSupervisingTeacher(row,userId)`|当前任课教师|有效教师 + `teacher_assignment.active`|
|`hasEffectiveCaseQualification(row,userId)`|本 case 处理资格|有效教师 + 无项目 membership 回避 +（当前任课教师 或 未撤销未到期 grant）|
|`isCurrentHandler(row,userId)`|本 case 当前处理人|case 非 CLOSED 且 `assigneeId==userId`|
|`canHandleCase(row,userId)`|正常办理|当前处理人 + 完整有效资格|
|`isQualifiedAssignee(row,userId)`|已结案历史读取|`assigneeId==userId` 且仍有完整资格，不看 CLOSED|
|`canReadCase(row,userId)`|全案读取|有效账号 + 无回避 +（当前任课教师 或 合法 assignee）|
|`canReadMaterial(row,material,userId)`|材料正文|材料收件本人 或 有全案读取资格|
|`canReadHandoff` / `canRespondHandoff`|交接必要摘要/回应|PENDING 仅指定接续人且仍有资格，或当前处理人；终态按当前本 case 读取资格|
|`canMakePersonnelDecision`|关联人员决定|`canHandleCase`，监督读取不能代办|
|`canRecoverCase`|依法收回|当前任课教师 + 无回避 + case 未结案 + 已有 assignee + 旧 assignee 已不能办理|

grant 到期使用项目 `Clock`，`expires_at == now` 即失效；grant 历史行、审计和材料正文在失权/收回后均保留。

### 2.2 入口核查

|入口|当前使用|
|---|---|
|`personnelCase`、`squareCases`、case 内嵌 materials/history|`canReadCase`/`canReadMaterial`；监督读取与 assignee 全案分离；学生只看本人材料|
|`material`、`myMaterials`|`canReadMaterial`；正文投影由“当前是否有权读正文”决定，不再看是否提交人|
|`requestMaterial`、`respondMaterial`、`reviewMaterial`、`withdrawMaterial`|写前与同键回放在事务内重新核当前收件人/当前 handler；回放重新投影当前撤回状态|
|`handoffCandidates`|SQL 同时核有效教师、角色、学校、回避、grant 到期|
|`handoff`、`myHandoffs`|统一 `canReadHandoff`；列表逐条过滤，无权项不导致整体失败|
|`create/respond/cancelHandoff`|`canInitiateHandoff`/`canRespondHandoff`/当前 handler；锁后重查来源版本与终态|
|`acceptCase`、`updateCase`、`closeCase`|受理/更新/结案分别核当前任课教师或当前 assignee|
|`recover`|`canRecoverCase`，不再用裸 grant/任课关系代替完整能力|
|`member-change`、`removal-vote` 的 personnel-decisions|从数据库解析 `member_change_id`/`vote.member_change_id` 到唯一 case，核当前 assignee|
|`TodoQueryService` 的 `MEMBER_CHANGE`、`MATERIAL_REQUEST`、`PERSONNEL_HANDOFF`|查询增加角色、学校、停用、核验、回避、assignee；点击待办与接口使用同一口径|
|`PersonnelCaseGrantAdminService.grant/revoke`|先锁 case，再取 grant scope/advisory 锁和 grant 行锁|

### 2.3 事务锁顺序

所有本轮人员事项写事务统一：

```text
只读预读资源 ID/关联（不据此写入或授权）
→ 按稳定 ID 锁 personnel_case
→ 需要协调资格时锁本 case grant（grant/revoke 先锁 case）
→ 按确定类型与 ID 锁 handoff / member_change / removal_vote / material
→ 锁后重查关联、资格、版本、终态
→ 业务写入、审计、幂等回执一起提交
```

|方法|锁顺序|
|---|---|
|`closeCaseOnce`|case → `UPDATE ... PENDING handoff WHERE case_id`|
|`respondHandoffOnce`|预读 caseId → case → handoff → 重查 `canRespondHandoff` 与原处理人资格|
|`cancelHandoffOnce`|预读 caseId → case → handoff → `UPDATE` 影响行数必须为 1|
|`recoverOnce`|case → 取消 PENDING handoff → 重查旧负责人完整能力|
|`createHandoffOnce`|case → 校验来源、当前处理人、候选、唯一 PENDING → insert|
|`reviewMaterialOnce` / `respondMaterialOnce` / `withdrawMaterialOnce`|预读 material.case_id → case → material → 重查版本|
|关联人员决定|预查 change/vote→case → case → change/vote → 重查关联与 assignee|
|grant/revoke|case → advisory scope → grant 行|

`V021` 只新增 `material_response`、`material_review` 和索引；未修改 V001～V020 校验和。

|反例|旧行为|本轮断言|
|---|---|---|

## 三、各问题修改摘要

### T01 材料投影与版本

- `GovViews.Material` 补齐 `recipientName`、`caseTitle`、`responses[]`（`version/authorId/content/evidenceRefs/createdAt/withdrawn`）、`reviews[]`、`canRespond/canReview/canWithdraw`；保留 `response` 兼容对象。
- 新增 `V021`：`material_response` 保存真实版本，`material_review` 固定审核的 `response_version`；旧数据只回填 `response_json` 能证明的当前版本，时间使用真实 `updated_at`，证据保持 `[]`，不编造历史。
- 撤回只将对应版本 `withdrawn=true`，`content=null` 占位；版本号、作者、时间保留。历史 v1 不因 v2 撤回消失。
- `reviewMaterial` 仍强校验 `responseVersion`，v1→v2 后审核 v1 返回 409 `SOURCE_CHANGED`，不产生审核记录。
- 材料详情、case 内嵌、本人列表和幂等回放共用同一投影函数；回放读取当前数据库状态。

### T02 使用时重查教师身份

- `GovRepository.accountEligible` 被替换为 `eligibleTeacher(squareId,userId)` 与 `activeVerifiedAccount(userId)`；前者加入 `user_role`、学校范围和账号状态。
- `handoffCandidates`、`TodoQueryService` 的 `MEMBER_CHANGE`/`PERSONNEL_HANDOFF` 批量 SQL 与策略语义一致。
- grant 创建时仍校验目标身份；运行期再次校验。只删除角色、保留 ACTIVE grant 时立即失权；恢复角色且 grant 仍有效时资格恢复，不生成新 grant。
- 旧 token 与新登录 token 都覆盖；同键回放重新执行当前资格检查。

### T03 收回

- `recoverOnce` 由 `canRecoverCase` 判断：当前任课教师、无回避、未结案、已有 assignee、旧 assignee 已不能 `canHandleCase`。
- 覆盖 grant 撤销/正好到期、账号停用、核验/角色失效、项目回避；仍合法者拒绝无理由抢回；结案事项不通过收回重开；无人受理不混成任意认领。

### T04 关联人员决定

- 新增 `casesForChange` 精确解析；无关联、多个关联、项目不一致分别拒绝，不用 `LIMIT 1` 或全局教师兜底。
- `decideOnce`/`decideVoteOnce` 先锁 case，再锁 change/vote，重查关联和 assignee。
- `openRemoval` 在移出表决通过时同步建立唯一 `personnel_case`，接续教师才能办理真实移出链路。
- `changeView.canDecide` 只对真正当前 handler 为真；监督教师可读但不可代办。

### T05 交接读取与投影

- `handoff`/`myHandoffs` 统一 `canReadHandoff`：PENDING 指定接续人只读必要说明；发起人必须是当前 handler；终态按当前本 case 读取资格，历史 from/to 不永久保留。
- `GovViews.Handoff` 补齐 `sourceUserId/recipientTeacherId/sourceCaseRevision/facts/unresolvedQuestions/decisionsNeeded/sourceName/recipientName/sourceValid/canRespond/canCancel`，保留 `fromUserId/toUserId` 兼容别名。
- 列表先按当前资格过滤再构造 `ListEnvelope`，`total` 为授权后总数；单条无权不让请求 500。

### T06 并发与协调

- 接受/取消/结案/收回/材料审核统一 case 先于子资源；`cancelPendingHandoffs` 在 case 锁内执行。
- grant/revoke 先锁 case，再取 advisory scope 和 grant 行锁，使撤权与接受/办理存在明确串行点。
- `cancelHandoffOnce` 检查 `UPDATE` 影响行数，不再出现 0 行却返回 CANCELLED。
- 双连接栅栏测试验证：持有 case 锁时，接受事务必须先等待 case，而不是先占 handoff 造成反向等待；旧负责人用接受前 revision 结案被拒。

## 六、剩余风险与后续

4. 未执行 Android 与云部署，因此不能宣称端到端关闭；关闭条件中的每一步均已在后端测试中覆盖。
