## 三、U02：未知提交时间与 V022

### 3.1 对外字段

```json
{"createdAt":"2026-11-01T10:00:00Z","createdAtConfidence":"EXACT"}
```

```json
{"createdAt":null,"createdAtConfidence":"UNKNOWN"}
```

`responses[]` 与兼容 `response` 使用同一 DTO；UNKNOWN 显式输出 null（不因全局 inclusion 省略），旧回执回放从当前数据库投影取时间。新提交/补交由一次服务器 Clock 写入真实时间+EXACT。

### 3.2 迁移与数据

- `V022` 把 `material_response.created_at` 改为可空，新增 `created_at_confidence`（非空，无默认值）、`legacy_recorded_at`、`time_source` 和恢复依据列；EXACT 必须非空、UNKNOWN 必须为空；V021 脚本与校验和不改。
- 只按 V021 的 `legacy-{material_request.id}` 规则识别回填行；旧 `updated_at` 进 `legacy_recorded_at`，`created_at=null`，`UNKNOWN/LEGACY_UNKNOWN`。正文、版本、作者、withdrawn 不变。
- 真实 UUID 新提交保持原时间并标记 `EXACT/SERVER_SUBMISSION`；不按“时间看起来可疑”猜测。
- 受控恢复：只有绑定同材料/版本/作者的 `operation_receipt` 才可通过 `material-time-recovery` 改为 `EXACT/RECOVERED_EVIDENCE`；无可靠证据保持 UNKNOWN。
