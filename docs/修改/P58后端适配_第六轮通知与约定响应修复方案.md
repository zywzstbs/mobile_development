## 4. N01：通知 FORMAT_ONLY 必须同时限制标题和正文（P2）

### 问题与位置

`notice/application/NoticeService.java` 的 revise，审查时约第 162～165 行仅比较 normalized content；约第 215 行却直接保存 request.title。

正文保持不变、标题从“周五考试”改为“考试取消”，使用 FORMAT_ONLY 即可能成功。contentVersion、接收快照保持不变，旧知悉回执继续有效。

主契约第 8.17 节规定 FORMAT_ONLY 只接受边界空白/换行规范化，实质变化必须 SUBSTANTIVE。

### 修复步骤

1. 先增加保持正文不变、只实质改标题的 HTTP 反例，证明当前实现错误接受。
2. 排版修订同时比较旧/新标题与旧/新正文的规范化值。
3. 沿用契约允许的边界空白、换行规范化；不要通过删除所有空格、忽略标点或大小写等规则吞掉实质改动。
4. 标题或正文任一发生实质改变，FORMAT_ONLY 拒绝，要求调用方明确选择实质修订。
5. 保留事务内当前管理资格、expectedRevision、禁止 FORMAT_ONLY 携带预览 token 的检查。
6. 拒绝时不得更改标题、正文、revision、displayRevision、contentVersion、接收快照、回执或 outbox。
7. 合法排版修订只按契约推进相应版本，不重置已有知悉。
8. 标题实质变更走 SUBSTANTIVE 时，沿用现有预览、来源版本、接收快照及回执隔离机制。
9. 不放宽幂等回放和撤权检查。

### 必测用例

- 只改标题实质内容、正文不变、FORMAT_ONLY：拒绝且无副作用。
- 只改正文实质内容：原有拒绝仍成立。
- 标题与正文都只做允许的边界空白/换行变化：成功，contentVersion 和快照不变。
- 中间文字、标点或空白变化超出允许规范化范围：不能被误判为排版。
- 相同原请求和幂等键重试：不重复推进版本。
- 实质标题修改通过 SUBSTANTIVE 成功后，新正文版回执不能被旧知悉替代。
- 无权、撤权、旧版本请求拒绝，数据库不变。

### 验收

Notify/NoticeP14IT 新反例真实执行；检查持久化记录和回执，不只断言 HTTP 状态。

## 5. N02：正式约定响应的数据映射

### 现有位置

- `delivery/DeliveryViews.java`：AgreementView、PlanUnitView、PlanShareView、PolicyView。
- `delivery/DeliveryService.java`：约定读取、agreementView、写入动作返回、renewOnce、replayAgreement、legacyAgreement。
- `delivery/DeliveryRepository.java`：约定、分项、提交、验收、贡献等查询。
- 人员交接关联查询和相关迁移。

当前 AgreementView 已扁平化 ownerId/dueAt/units/reviewerPolicy，但 units 仍主要是计划字段，缺少运行状态及事实记录。

### 需要逐项落实的字段

下表为重点缺项，执行时必须对照完整 R_DELIVERY_01，不把本表当作可省略其余字段的依据。

|字段|要求/来源原则|
|---|---|
|units[].status|对应实际正式分项状态，不能复制整个任务状态|
|units[].revision|对应分项资源的真实并发版本|
|units[].dueAt|从对应约定/分项的有效截止依据取得，不使用任意当前时间|
|units[].acceptance|对应当前应展示提交版本的实际验收记录|
|acceptance 的 id、submissionId、reviewerId、kind、decision、reason、acceptedAt、revision|来自真实验收与持久化版本依据|
|acceptance.checks[]|真实逐标准核对，正确绑定 unitId/criterionId/met|
|units[].contributionConfirmations[]|本人贡献确认，绑定 acceptanceId/submissionId/userId/statement/createdAt|
|units[].shares[].accepted|对应本版本人明确接受事实，不等同上传、验收或贡献确认|
|units[].shares[].displayName|授权范围内的真实用户展示名|
|reviewerPolicy.displayName|按契约适用的详情/交接分支返回|
|memberChangeId|真实交接续约来源人员变更 ID，仅适用分支返回|
|renewalReason|真实续约说明，不能复制无关操作理由|
|reviewerAcceptanceInherited|按实际继承条件计算，不能固定 true/false|

### 步骤

1. 列出当前表和 JSON 快照中能够直接取得的事实，不先写 DTO 再随意填值。
2. 对每个字段明确关联的 agreementVersion、unitId、submissionId、acceptanceId、memberChangeId。
3. 核查旧约定读取是否应固定历史计划，避免将另一版分项或后来无关提交拼接到旧约定。
4. 区分“没有验收记录”与“验收记录缺字段”。尚无子记录时按通用空子结构规则；记录存在则完整返回，不用空对象隐藏真实记录。
5. 区分 shares.accepted、约定 acknowledgements 与 contributionConfirmations，不互相冒充。
6. 对无法从当前数据可靠获得的字段，确定是否需要新增持久化信息或迁移；历史不可恢复的情况单独记录，禁止编造历史事实。
7. 条件字段只在相应分支返回，普通约定不能随意生成交接来源。

### 验收

字段映射表完整，来源和版本可追溯；缺口有明确处理决定，不能仍以“后续补齐”交付本轮 N03。

## 6. N03：补齐完整响应投影

### 步骤

1. 为正式约定响应设计专用 DTO，必要时与输入计划 DTO 分离，避免共享 PlanUnitView 导致所有计划输入被迫携带只读状态。
2. Repository 按约定/分项集合批量查询实际状态、验收、确认及人员信息，避免每个分项和每个份额无限追加查询。
3. 在一致的读取事务/快照下构造关联投影，防止验收与确认来自互不一致的瞬间。
4. 正确处理 TODO、REVIEW_PENDING、PASSED、RETURNED，以及部分分项通过的情况。
5. 验收返回与提交序号对应，撤回后新提交不得套用上一条提交的验收。
6. 贡献确认保持本人事实和原验收绑定，不能把提交人视为唯一贡献者，也不能给所有份额补 confirmed。
7. 核对正式约定读取、响应字典指定的 DELIVERY-15/17 及其他实际返回 AgreementView 的动作，确保对应结构完整。
8. 交接续约保留来源人员变更、方案/约定版本和真实接任关系；不能在投影时提前执行移人或接任。
9. 只读投影不能产生确认、验收、版本推进或正式成绩变化。
10. 保留当前成员/资源访问控制，历史记录不因用于响应补齐而绕过权限。
11. 若新增数据库结构，使用新迁移，补空库和旧库升级测试；不修改 V001～V027。

### 必测场景

- 新约定尚无提交：基础字段齐全，缺失子记录按契约表达，不伪造验收。
- 一个分项待验收、一个已通过：状态分开，任务整体不错误显示完成。
- 验收返回后重新提交：展示正确提交/验收绑定，旧记录保留。
- 只有一名贡献者确认：响应只包含该真实确认，不补其他人。
- 某份额本人尚未接受：accepted 为真实状态，不因他人已接受而变 true。
- 约定调整产生新版本：新旧读取不混合无关事实。
- 交接续约：来源 ID、理由、验收继承信息与真实业务一致。
- 离组或失权读取/回放被拒绝。
- GET 前后数据库无写入变化。

## 7. N04：新增响应字段不能破坏历史幂等回放

第五轮已经保留旧 plan 结构与新顶层结构的历史回执恢复，本轮继续扩充 DTO 时必须同时维护兼容。

### 步骤

1. 建立三类回执样例：旧 plan 包装、第五轮顶层结构、本轮完整结构。
2. 调整 executeHistorical/replayAgreement 的调用方适配逻辑，仍先按真实 taskId 等资源检查当前权限。
3. 明确首次动作返回的固定结果与 GET 当前详情之间的区别；不能用后来的验收、确认或当前约定替换原操作成功结果。
4. 历史回执缺少新增事实时，只有可追溯的同版历史数据才能补；不能读取“最新一条”冒充当时事实。
5. 不全局关闭未知字段校验，不清空历史回执，不重新执行原写入。
6. 防止旧缓存中缺少 primitive boolean/int 被默认反序列化为 false/0 后假装成真实事实。
7. 没有可恢复证据的分支明确记录并形成兼容方案，不把未经定义的 500 作为完成状态。

### 必测用例

- 三类结构均能按既定策略恢复，不出现未知字段或缺字段造成的非预期 500。
- 相同 key/body 不增加约定、验收、贡献、移人或 outbox。
- 原操作后新增了验收/确认，重放不能冒充返回后续操作的结果。
- 同键异正文冲突。
- 普通约定与交接续约回放都核当前权限，离组后拒绝。
