### 3.3 2026-11-07 复核更正（L01 通知源版本）

> 2026-11-07 复审核实，首轮基线使用 `isNumber()+intValue()`，可把小数截断，也缺少正数与业务上限校验。后续修复改为精确整数和 1～999999999 校验，并在接收人循环前完整验证。修改后的结果以修复回告和新日志为准，历史数据及真实来源跳转另行验收。

- **更正前（首轮）**：§3.2 的 L01 行写“只接受 JSON 整数”，与实际基线 HEAD `66b856b` 的 `notice/application/NoticeOutboxWorker` 不符。基线代码是 `payload.path("sourceVersion").isNumber() ? intValue() : null`：`1.75` 截断成 `1`，超 int 范围没有精确转换，缺字段写 null，且 `catch (Exception ignored)` 同时包住解析与全部接收人 SQL，无法保证“没有部分通知写入”。
- **更正后（本轮）**：见[首轮审查问题修复回告](P62至P71_首轮审查问题_修复回告_20261107.md)。要点：版本必须是 JSON 整数节点、可无损转 int、且在 1～999999999；所有接收人在 INSERT 之前完成校验；坏载荷零通知写入且 `processed_at` 保持 null；SQL 异常不再被吞掉，整批 drain 事务回滚。
- **仍未关闭的部分**：历史 `notification.source_version` 的空值/伪值盘点（含“1.75 被截断成合法 1”这类无法自动识别者）、按证据回填、真实客户端来源跳转，以及公告与聊天提及的分别验收。按本指南 §5.5 只做只读盘点，不批量补默认值，不把坏事件标成投递成功。
- **统计口径**：首轮的“单元 91、集成 279”是首轮基线数字；本轮新增用例后的实际数量以修复回告与当次日志为准，不沿用首轮数字，也不设凑数目标。

## 4. S1 修改内容

### 4.1 A03 恢复资格

- 新增 `AccountEligibility`：`restorationEligible` 只对“`account_status=DISABLED` + `disabled=true` + `eligibility_source=ADMIN_DISABLED`”为真；待审、驳回、`IMPORT_DISABLED`、`LEGACY_DISABLED_*` 一律为假。A03 读投影与 A04 事务内恢复判定共用该方法；停用前置条件抽为 `disableEligible`，语义与错误消息不变。
- `PlatformViews.AccountUser` 增加 `boolean restorationEligible`（`data.user.restorationEligible`），为**附加字段**，列表 A02 结构未变。
- 契约提示：Android 需确认字段嵌套；该字段是“目标事实”，不代替 `PLATFORM_ACCOUNT_MANAGE`、当前范围、版本、再认证和事务内复查。

### 4.2 A03 子资源与摘要范围

- `activeGrantsForUser`、`teachingForUser`、`activeGrantCount`、`teachingCount` 增加 `(platform, grantId)` 范围参数：学校范围授权用课程真实 `square.school_id` 过滤；平台范围不过滤。账号详情摘要计数与明细使用同一范围，避免“账号同校但课程跨校”时泄露课程名、能力、期限或计数。
- 拆掉原先复用的 `ClassGrantBrief` 五参兼容构造器（它把课程名塞进 `userId` 字段），改为 `AssistantGrantRow`（课程详情，带 grantId/版本）与 `UserCourseGrantRow`（账号详情，只读投影），消除字段语义混用。

### 4.3 分页与按 ID 装载的范围复核

- `usersByIds`、`applicationsByIds`、`coursesByIds` 增加带 `(platform, grantId)` 的范围变体；续页按当前范围重载，不再只信 15 分钟快照。
- `PlatformReadService.page` 在游标分支用当前筛选重算的可见 ID 复核快照：任一快照 ID 已不可见（账号转校、授权范围收缩、申请/课程状态变化）即抛 `CURSOR_EXPIRED`（409），客户端从首页重读；快照语义与 `total` 不再跨范围沿用。
- 首次页仍按原 ID 查询过滤；续页即使通过复核，SQL 装载仍带范围条件（纵深防御）。

### 4.4 A14 超管目录

- 仅全平台范围授权的操作者可用；学校范围授权明确 403（`FORBIDDEN`，消息“超级管理员目录只对全平台范围授权开放”）。
- 现态目录每用户一条：优先 `ACTIVE` 授权，无当前授权时取最近撤销记录；不再因撤销后重授出现同一用户多条。
- 目录仍列出学校范围授权条目（平台操作者可见），状态按授权/账号实际值显示。
