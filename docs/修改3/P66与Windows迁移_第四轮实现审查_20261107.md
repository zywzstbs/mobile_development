## T4-1 / P2：日志初始化失败后遗留子进程

位置：`scripts/pg-test-process.ps1` 的 `Invoke-BoundedProcess` 第 101～106、129～138 行，以及 `Start-ResidentProcess` 第 176～185 行（以审查快照为准）。

两个函数都先 `Process.Start()`，再打开 stdout/stderr 日志。如果日志路径不可写、被独占占用或实际为目录，打开日志抛出异常，但已启动的子进程没有被结束。短命令尚未进入 `WaitForExit(timeout)`，配置超时也不会生效；常驻函数尚未返回句柄，调用者拿不到 `$resident` 清理。

短命令分支还有同一路径的问题：两个复制任务都为空时，管道赋值使 `$pending` 为 `$null`，StrictMode 下访问 `$pending.Count` 再次抛错，遮住原始日志错误并跳过后面的释放逻辑。

影响：日志 I/O 失败时可能遗留 initdb、postgres 或其他调用进程，诊断也可能失真。正常全量测试不触发此分支。本轮使用独立测试子进程复现，没有故意破坏真实 PostgreSQL 日志。

### 复现

仓库根目录下用 PowerShell 7 执行：

```powershell
& './docs/修改3/审查复现/ReviewFourthProcessFailure.ps1'
```

探针把自己创建的目录作为 stdout 文件，确定性触发日志打开失败；子进程写 PID 标记后等待 30 秒。探针等待 2 秒检查，再按 PID、程序路径和创建时间回收自己的进程。当前漏洞存在时返回 1。本轮输出：

```text
Bounded threw: PropertyNotFoundException: The property 'Count' cannot be found on this object.
Bounded childAliveAfterFailure=True
Resident threw: MethodInvocationException: ... Access to the path ... is denied.
Resident childAliveAfterFailure=True
```

记录：`.tools/logs/review-fourth-process-failure.log`。测试进程均已回收；target 下的探针文件保留用于核对。

### 修改步骤与验收

1. 在启动进程之前打开两个日志流；第二个流打开失败时也必须释放第一个。不要仅上移语句而遗漏 finally。
2. 用完整的资源生命周期覆盖日志打开、启动、异步复制初始化、等待和返回。记录是否已启动、是否已成功交接；交接前异常时，只结束本函数刚创建的进程树，并有界等待。
3. 常驻函数成功返回后才将所有权交给调用者；失败时不能遗留进程或日志句柄。禁止按名称或端口批量结束进程。
4. 把复制任务列表明确包装为数组，例如 `$pending = @(@($stdoutCopy, $stderrCopy) | Where-Object { $null -ne $_ })`。清理不能遮住原始异常。
5. 为两个函数补 stdout 打开失败、stderr 打开失败、启动失败测试，断言原始错误可识别、无子进程残留、日志流已释放；还应覆盖启动后复制初始化失败的清理路径。现有“exe 不存在会抛错”断言不足以验证错误来源。
6. 重跑 helper 自检、本报告探针和完整 `verify`。保留正常 pg_ctl 启动逻辑，不修改 PostgreSQL 二进制。
