## 1. 已核实的后端事实

> **2026-11-07 复核更正**：本节按首轮审查的实际代码重写。原文“其余字段按动作白名单校验”“`payloadDigest` 提供时必须一致”“`IdempotencyService.execute` 在所有分支先要求 `reauthToken`”三处与基线不符，已按下列事实替换。严格动作字段校验、密码边界、新协议必填摘要及回放入口仍是 **S3 待实现项**（见 §7），本文更正只提高描述准确性，不把功能记作已完成。

- A17 `POST /api/v1/auth/reauthentications` 现有正文：`password、operationId、action、targetType、targetId、expectedRevision、precondition、decision、reason、note、status、targetUserId、payloadDigest`（`PlatformRequests.ReauthenticationRequest`，固定 DTO）。全局未知 JSON 字段由 Jackson 拒绝；但 `AdminCommands.reauthentication()` 只校验**当前动作需要**的字段，**部分“DTO 已知、动作不适用”的字段会被静默忽略**：例如 `TEACHER_APPLICATION_DECIDE` 请求里附带 `status/reason/targetUserId` 不会逐项报错，`ACCOUNT_STATUS_CHANGE` 附带 `decision/note/targetUserId` 同理。严格的动作字段白名单是 S3 待实现项。
- 密码当前只在 `AdminReauthenticationService.reauthenticate` 首行显式判 null；空串会走到 `passwordEncoder.matches` 并返回 401 `INVALID_CREDENTIALS`，不是 422。最大长度与首尾空白的严格处理同属 S3 待补项。
- `payloadDigest` 的比较条件是“非 null 且非 blank”：省略、空串、纯空白都会**跳过**比对，只有提供非空白值时才要求等于服务端完整摘要。
- 后端摘要：`AdminPayloadDigest` 用 `CanonicalJson` 排序后 SHA-256 小写十六进制，字段为 action、targetType、targetId、expectedRevision、precondition、decision、status、reason、note、targetUserId；`reason/note/decision/status` 先 `strip()`，空白记 null；不包含 password、reauthToken、operationId、payloadDigest。
- 再认证令牌：5 分钟 TTL、服务端 `Clock`、绑定 actorId + `auth_session.id` + operationId + 动作/目标/版本/前置条件 + 完整摘要；库存 SHA-256 指纹，只在回包出现一次。核销与业务同事务，核销时再次检查未过期。
- 写入：`X-Operation-Id` 必填，与 `Idempotency-Key` 是两个独立字段；锁顺序为公共幂等锁 → `platform_admin_lock` → actor+operationId 事务锁 → 再认证行 → 业务资源；审计、令牌核销、业务、`admin_operation`、幂等快照任一失败整体回滚。
- 已提交回放：**“所有分支先要求非空 `reauthToken`”的实际代码在 `PlatformWriteService.execute` 入口**（`reauthToken == null || isBlank()` 即 403 `REAUTH_REQUIRED`），公共 `IdempotencyService` 本身不知道 `reauthToken` 字段。已有回执分支据此不校验令牌的消费或 TTL；`admin_operation` 按 actor+operationId 保存回执与完整摘要，缓存默认 7 天。
- 目标类型现状（内部/回执）：A11 `TEACHER_CLAIM`，A12 `CLASS_GRANT`，A15/A16 `USER`；A13 读取时映射为 P71 文案（`COURSE_CLAIM`、`ADMIN_GRANT`、`SUPER_ADMIN`）。
- 公开的五个六段摘要向量已用独立实现（LF 连接、UTF-8、SHA-256、Base64URL 无 padding）逐条复算，结果与指南 §5.2 完全一致；含空理由与字段内 LF 的向量也一致。

### 4.4 A16 撤销超管（绑定 grantId）

A17 与 A15 相同目标，但第 4 段为当前授权 revision、第 5 段空串、第 6 段为撤销理由；服务端在签发时解析唯一 ACTIVE 授权并绑定 grantId。写入 `POST /api/v1/admin/super-admins/{userId}/revocations`，回执 `resource.id=userId`、`status=REVOKED`、`revision=原授权+1`。撤销后重授再撤销时，旧令牌必须因 grantId 不同而拒绝。

### 4.5 回包丢失与未知结果

1. 发送写入，服务端提交后代理断开或客户端超时。
2. 客户端保留原正文、operationId、幂等键、请求号。
3. 用同正文原样重发；已提交分支返回存档回执（D9），不重复写业务、审计、授权或令牌核销。
4. 若返回 403 `REAUTH_REQUIRED`/`REAUTH_CONTEXT_MISMATCH`，不得推出“未提交”，先按 operationId 查询 `admin_operation`/审计；查询手段在 S3 前单独冻结，不能先发明只读路由。
5. **必须加入的反例**：首个回包丢失后，后续重试再收到任何 4xx（缺操作头、缺令牌、令牌过期、`REVISION_CONFLICT`、`INVALID_STATE_TRANSITION`、`IDEMPOTENCY_KEY_REUSED`），客户端仍保持“未知”，不能用该 4xx 清除原记录；只有按原编号/原键查到数据库“未提交”的证据后才可转终态。旧 P70 的 `notSubmitted` 需按此重新核对来源，`CONTRACT_ERROR` 不属于通用证明。

## 5. 错误语义登记（六类写入）

**前提（2026-11-07 复核补充）**：当前拒绝语义仍未冻结，客户端确认集合为空。仅在协议已冻结、具体路由/协议版本/HTTP+code/产生阶段已逐项登记、该逻辑操作为首次业务尝试且没有更早未知时，已确认规则才可作为本次未提交的证据。再次尝试的 4xx、缺操作头、缺令牌或令牌过期不能清除原操作的未知状态。

| 场景 | HTTP/code | 可能阶段 | 当前处理分支能否证明本次尝试未执行，以及历史状态限制 |
|---|---|---|---|
| Jackson 未知字段拒绝 | 422 `FIELD_NOT_ALLOWED` | Jackson 读入前 | 本次读入分支未调用业务；原编号可能已有历史提交，是否可进入确认集合另需冻结 |
| 缺 `X-Operation-Id` | 403 `REAUTH_REQUIRED` | 控制器入口 | 本次控制器拒绝；请求甚至未准确关联原业务，不能推定历史操作不存在 |
| 缺令牌或查无令牌 | 403 `REAUTH_REQUIRED` | 写入入口（`PlatformWriteService.execute`） | 当前拒绝分支没有新执行；旧提交与缓存过期、令牌清理可以同时存在 |
| 令牌过期 | 403 `REAUTH_EXPIRED` | 核销 | 核销失败的当前事务应回滚；历史提交另查 |
| 已消费或上下文不符 | 403 `REAUTH_CONTEXT_MISMATCH` | A17 或写入核销 | 已消费可来自先前成功，保留未知并读原回执 |
| 版本冲突或状态不允许 | 409 `REVISION_CONFLICT` / 409 `INVALID_STATE_TRANSITION` | 锁内业务 | 本次事务的结果，可能已有原操作或其他操作改变目标 |
| 同键异文 | 409 `IDEMPOTENCY_KEY_REUSED` | 幂等快照比较 | 当前请求冲突，原键绑定操作可能已经成功 |
| 请求与响应大小错误 | 413 | 请求前置或事务提交后响应侧 | 必须区分请求前置 413 与事务提交后响应侧 413；HTTP+code 可重合 |
| 5xx、代理错误、断连、损坏回执 | — | 任意 | 结果未知，按原编号/原键核对 |

登记要求：每条规则都要登记产生阶段（Jackson/控制器/事务内哪一步）与数据库副作用证据；签收栏由双方填写实际负责人与日期。只有实际签收后，Android 才能逐项登记确认集合。
