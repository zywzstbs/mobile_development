## 2. 已冻结的后端规则

### 2.1 平台范围

授权记录显式保存 `PLATFORM` 或 `SCHOOL`。列表、详情、计数和写入都按该记录过滤。不把登录用户的 `schoolId` 当成管理范围。

- `PLATFORM`：全部学校。
- `SCHOOL`：只含列出的学校。
- A15 没有范围字段。授权人若是平台范围，新授权也是平台范围并固定七项能力；若只有学校范围，则只授予目标用户所在、且授权人已经覆盖的那一所学校。
- A14 返回全部超管目录，不按学校截断。客户端用它计算人数，最后一位保护仍以数据库事务为准。学校范围的授权人可以看见平台超管，但不能撤销平台范围授权。

### 2.2 超管前置条件

目标必须是 `accountStatus=ACTIVE`、`disabled=false`、`identityStatus=VERIFIED`、`eligibility_source=VERIFIED_ACTIVE`，并且已经有密码哈希。注册教师通过后身份仍可能是 `PENDING`，这种账号不能被 A15 授予。HTTP 禁止自授。CLI 初始化可以指定操作者本人的已有账号，因为当时还没有另一位超管。

### 2.3 没有版本号时的前置条件

不要求客户端填 `1`。

| 动作 | 版本 | 前置条件 |
|---|---|---|
| `ACCOUNT_STATUS_CHANGE` | 用户 `revision` | 无 |
| `PASSWORD_RESET_REQUEST` | 不填 | `TARGET_ACCOUNT` |
| `TEACHER_APPLICATION_DECIDE` | 申请 `revision` | 无 |
| `COURSE_CLAIM_DECIDE` | 认领 `revision` | 无 |
| `ADMIN_GRANT_REVOKE` | 班级授权 `revision` | 无 |
| `SUPER_ADMIN_GRANT` | 不填 | `NO_ACTIVE_GRANT` |
| `SUPER_ADMIN_REVOKE` | 平台授权 `revision`，不是用户版本 | 无 |

客户端若给没有版本的动作填写 `expectedRevision`，返回 422。前置条件必须与上表一致，不能另造。

### 2.4 A17 与摘要

`POST /api/v1/auth/reauthentications` 保持登录，不创建会话。当前客户端只发 `{"password":...}` 会得到 422，因为缺少绑定字段。

正文：

```json
{
  "password": "<本人本次输入，不 trim>",
  "operationId": "op_1",
  "action": "TEACHER_APPLICATION_DECIDE",
  "targetType": "TEACHER_APPLICATION",
  "targetId": "application_1",
  "expectedRevision": 3,
  "precondition": null,
  "decision": "APPROVE",
  "reason": null,
  "note": "核验通过",
  "status": null,
  "targetUserId": null,
  "payloadDigest": "可选；若填写必须等于服务端摘要"
}
```

`operationId` 同时放在后续写入的请求头 `X-Operation-Id`。幂等键仍是 `Idempotency-Key`，两者不是同一个字段。

摘要是下列对象的规范 JSON（键排序、UTF-8、整数为数字、缺省为 `null`、`reason/note/decision/status` 先 trim，空白变 `null`）的 SHA-256 小写十六进制。不含 `password`、`reauthToken`、`payloadDigest`、`operationId`。

```json
{"action":"TEACHER_APPLICATION_DECIDE","decision":"APPROVE","expectedRevision":3,"note":"核验通过","precondition":null,"reason":null,"status":null,"targetId":"application_1","targetType":"TEACHER_APPLICATION","targetUserId":null}
```

该向量摘要：`66ef99ba119e7343ee5d3de2cee54544fedfa176435268bf8b8b2f6e141dea59`。

令牌随机、只返回一次，库存 SHA-256，5 分钟有效，绑定操作者、会话、操作编号、动作、目标和摘要。更新令牌后，同一 `operationId` 与同一业务内容仍是同一笔操作。

### 2.5 回执

写入成功且事务提交后返回：

```json
{
  "operation": {
    "id": "op_1",
    "action": "TEACHER_APPLICATION_DECIDE",
    "targetType": "TEACHER_APPLICATION",
    "targetId": "application_1",
    "status": "COMMITTED",
    "resultingRevision": 4,
    "auditId": "audit_1"
  },
  "resource": {
    "id": "application_1",
    "status": "APPROVED",
    "revision": 4
  }
}
```

A05 不返回这组字段，也不返回重置受理回包。没有结果版本的新授权，`resultingRevision` 使用新授权自身的版本 `1`，不伪造用户版本。

### 2.6 总览 `exceptionsPending`

真实计数，不是固定 0。统计当前范围内：`eligibility_source` 属于历史停用或导入停用，或者 `disabled=true` 但 `account_status` 不是 `DISABLED` 的账号。没有这类账号时结果就是 0。

### 2.7 课程 `claimStatus`

目录和教学课程投影使用：

- `PENDING`：没有当前教师，且有待审认领。
- `APPROVED`：已有当前教师。这是平台侧“归属已确定”，不是教师工作区的 `ACTIVE`。
- `NONE`：没有当前教师，也没有待审认领。

认领明细 `claims.status` 只返回 `PENDING/APPROVED/REJECTED`。`CANCELLED` 不放进该数组，避免冒充驳回。

### 2.8 错误码

管理资源不存在是 `RESOURCE_NOT_FOUND`。`/api/v1/admin/**` 上不存在的路由是 `PATH_NOT_FOUND`。其他历史 404 仍是 `NOT_FOUND`。未开放渠道是 `501 ENDPOINT_NOT_IMPLEMENTED`。版本冲突是 `REVISION_CONFLICT`。最后一位恢复管理员是 `LAST_ACTIVE_SUPER_ADMIN`。

### 2.9 管理审计的可见集合

`A13` 不再把整张审计表当成管理审计，只投影精确命中 `action + resourceType` 分类组合的事件。当前集合：

| action | resourceType | 对外 action | result | reason |
|---|---|---|---|---|
| `ACCOUNT_DISABLED` | `USER` | 同名 | `SUCCEEDED` | 原文 |
| `ACCOUNT_RESTORED` | `USER` | 同名 | `SUCCEEDED` | 原文 |
| `PASSWORD_RESET_REQUESTED` | `USER` | 同名 | `SUCCEEDED` | 原文 |
| `SUPER_ADMIN_GRANTED` | `PLATFORM_ADMIN_GRANT` | 同名 | `SUCCEEDED` | 原文 |
| `SUPER_ADMIN_REVOKED` | `PLATFORM_ADMIN_GRANT` | 同名 | `SUCCEEDED` | 原文 |
| `ADMIN_GRANT_REVOKED` / `CLASS_GRANT_REVOKE` | `CLASS_GRANT` | `ADMIN_GRANT_REVOKED` | `SUCCEEDED` | 固定空串 |
| `REGISTRATION_APPROVE` | `REGISTRATION` | `TEACHER_APPLICATION_APPROVED` | `SUCCEEDED` | 固定空串 |
| `REGISTRATION_REJECT` | `REGISTRATION` | `TEACHER_APPLICATION_REJECTED` | `REJECTED` | 固定空串 |
| `TEACHER_CLAIM_APPROVE` | `TEACHER_CLAIM` | `COURSE_CLAIM_APPROVED` | `SUCCEEDED` | 固定空串 |
| `TEACHER_CLAIM_REJECT` | `TEACHER_CLAIM` | `COURSE_CLAIM_REJECTED` | `REJECTED` | 固定空串 |
| `TEACHER_APPLICATION_APPROVED` | `REGISTRATION` | 同名 | `SUCCEEDED` | 固定空串 |
| `TEACHER_APPLICATION_REJECTED` | `REGISTRATION` | 同名 | `REJECTED` | 固定空串 |
| `COURSE_CLAIM_APPROVED` | `TEACHER_CLAIM` | 同名 | `SUCCEEDED` | 固定空串 |
| `COURSE_CLAIM_REJECTED` | `TEACHER_CLAIM` | 同名 | `REJECTED` | 固定空串 |

`TEACHER_APPLICATION_*` 与 `COURSE_CLAIM_*` 是 HTTP A08/A11 实际写入的动作名，旧 CLI 动作仍映射到同一对外动作；两组都命中同一分类语义（第二轮补入）。

未登记的 `action + resourceType` 组合不进入 `A13`、`A01.recentOperations` 和 `A03.managementRecords`，即使调用者持有 `AUDIT_READ`。`SUPPORT_*`、`PERSONNEL_CASE_*`、`AUTH_*`、聊天、任务、成绩、文件类事件默认不在集合内。

`result` 由分类表直接给出，不再用“action 里包含 `REJECT`”推断，避免把未知失败事件标成成功。被固定为空串的 `reason` 原文仍保存在 `audit_event`，只是不投影给管理页面。

`scope` 按目标真实归属计算：用户事件取该用户所在学校；教师申请取申请提交的学校；课程认领取广场所在学校；已撤销的助理授权取该授权原本挂的广场；平台授权事件取该授权自身的实际范围（`PLATFORM` 或学校）。不再用操作者学校兜底，也不把无法确定范围的学校事件放行到全平台。

游标版本改为 `audit-v2`。此前保存的审计游标一律失效，客户端收到游标错误后重新从第一页读取。

### 2.10 总览的权限门槛

`A01` 的三项计数各需要一项能力：`exceptionsPending` 需要 `ACCOUNT_READ`，`teacherApplicationsPending` 需要 `TEACHER_REVIEW`，`courseClaimsPending` 需要 `COURSE_GOVERNANCE`。

- 缺任一项：`403 FORBIDDEN`，`message` 写明“总览统计权限不足：缺少 …”。响应里不出现 `counts`，也不返回 0 冒充统计结果。同一账号已获授权的 `A02/A03` 仍正常。
- 三项齐全但没有 `AUDIT_READ`：`recentOperations` 返回空数组。含义是“当前可见的操作集合为空”，不是“没有操作发生”。
- 全部具备：真实计数，`recentOperations` 为按 2.9 过滤后的最近 20 条。

客户端不要用“字段缺失即 0”渲染，也不要因为空数组就提示异常。这是本轮的后端策略，客户端适配尚未确认。

### 2.11 回执回放的目标授权

回放分两条路径：同一幂等键的重复请求，以及同一 `actor + X-Operation-Id` 换幂等键的请求。两条都只重做“当前操作者资格”和“当前目标可见范围”，不重跑已通过的业务前置条件，返回原回执。

超管授予/撤销的回放范围，取该操作审计记录指向的那条平台授权在此刻的实际范围，不从目标用户当前的授权状态反推。因此目标被重新授权、或目标版本变化，都不改变旧回执的可读性；但操作者本人被撤权、停用或失去目标范围时，回放返回 `403 FORBIDDEN`，不回执。

## 4. 资格来源

`eligibility_source` 记录账号为什么处于当前状态。恢复只接受 `ADMIN_DISABLED` 回到 `VERIFIED_ACTIVE`。`PENDING_REVIEW/REJECTED` 不能靠 A04 绕过审核。历史 `disabled=true` 且原状态为 `ACTIVE` 的账号迁成 `DISABLED` + `LEGACY_DISABLED_UNCLEAR`，不能靠恢复猜成已审核。

“最后一位可恢复管理员”的判定要求同时成立：账号 `ACTIVE` 且未停用；持有 `SUPER_ADMIN` 角色；有 `ACTIVE` 的平台授权；该授权具备 `PLATFORM_ACCOUNT_MANAGE` 与 `PLATFORM_SUPER_ADMIN_MANAGE`；授权范围覆盖 `PLATFORM`；账号有可用密码凭据。只挂学校范围授权的管理员不计入，多个学校的管理员并集也不能替代一个全平台管理员。

## 5. 首位超管

```text
java -jar app.jar --spring.profiles.active=cli --app.cli.enabled=true \
  --app.cli.command=init-super-admin \
  --app.cli.user-id=<已有账号> \
  --app.cli.reason=<1至500字>
```

不接受 `app.cli.actor` 冒充审核人。口令沿用该账号已有的安全设置，不写进命令、文档或日志。生产执行需另有授权。本轮没有创建生产超管。

重复执行的行为按当前库状态区分：

- 账号没有平台授权且符合资格：原子写入授权、七项能力、`PLATFORM` 范围、`SUPER_ADMIN` 角色和审计。
- 已有授权，且角色、能力、范围、账号状态全部符合：打印 `already-active`，授权 ID 不变，不追加历史记录。
- 已有 `ACTIVE` 授权但缺角色/能力、范围不符或账号不可用：命令失败并打印人工受控修复说明。不会自动补齐能力，也不会把学校授权升级成全平台。
- 只有 `SUPER_ADMIN` 角色而没有有效授权：该账号不算有效管理员（不进入恢复计数）。由可信 CLI 显式指定该用户时，按“无授权且符合资格”补齐，同样写入审计。

普通用户导入（`admin/import-users`）仍然拒绝文件声明 `SUPER_ADMIN`，并且不改动已有管理员的停用状态、身份核验状态和口令；这些变更只能走受控管理操作。导入会在管理约束锁内按账号 ID 顺序加锁、整批一个事务，批次前后比较可恢复管理员数量，从正数降到 0 就整批回滚。

## 6. 仍待双方设计，本轮不猜路径

| 事项 | 现有后端 | 未做 |
|---|---|---|
| 受理路由 | `OperatorGrantAdminService` 与工单访问控制 | 管理元数据、候选和动作的公开路径 |
| 单人员事项授权 | `PersonnelCaseGrantAdminService` | 平台路由不读案情；接受与接续规则的 App 合同 |
| 助理候选 | 当前任课教师与课程权限 | 分页候选投影，只给当前任课教师 |
| 助理有效期 | 默认学期结束 | 新字段的上下限、过期失效和旧请求兼容 |
| 独立教师撤权 | 任课与转交服务 | 影响预览和审计；停用账号不能代替撤权 |
| 本人改密 / 激活 | 登录与会话 | 一次性凭据和配套页面；没有渠道就保持未开放 |
| 已加入课程 | 现有课程成员关系 | 先核对现有投影，不把课程目录当成已加入列表 |

这些事项标记为：后端旧能力仍在，平台页面路径未实现，客户端页面未完成，未验收。
