## 2. T3-1 实现：写入前即受私有保护

### 2.1 新增 `PrivateCredentialFiles`

`package-private final class PrivateCredentialFiles implements AutoCloseable`，是凭据文件与临时用户 JSON 的唯一写入通道：

- **权限模型选择**：`selectPermissions(Set<String> supportedViews)`——有 `posix` 视图用 POSIX（目录 0700、文件 0600），有 `acl` 视图用 Windows ACL，两者都没有直接抛 `PrivateFileException("文件系统既不支持 POSIX 权限也不支持 ACL，拒绝写入凭据")`。**不再有"不支持就跳过"的分支。**
- **写入顺序**：`writePrivateCredentials(file, content)` 先在目标父目录下建 `.gulupai-private-*` 暂存目录 → 收紧暂存目录 → 建暂存文件 → 收紧暂存文件 → 写内容 → 回读校验 → 以 `ATOMIC_MOVE + REPLACE_EXISTING` 发布到目标（不支持原子移动时退化为同目录重命名，仍不把明文写到宽权限目标）→ 发布后复核目标权限与内容。明文第一次落盘时就在私有目录/私有文件里。
- **读取既有文件**：`readExistingPrivateCredentials(file)` 先校验权限，不满足则先收紧再复核后读取；文件不存在返回 `Optional.empty()`。旧版本遗留的宽权限文件在被读取时就被收紧。
- **Windows ACL**：DACL 只保留一条 `ALLOW` 规则，主体是 `TrustedOsIdentity.windowsAccountName()` 查出的当前账户；文件权限为读/写/执行相关 12 项，目录另加 `FILE_INHERIT | DIRECTORY_INHERIT`。写入后回读校验规则数、类型、主体、继承标志与权限集合，不比较任何本地化组名文本。
- **临时用户 JSON**：`createPrivateJson(value, mapper)` 在 `java.io.tmpdir` 下建 `gulupai-private-*` 私有目录，先收紧目录、再建 `payload.json` 并收紧，然后才序列化；`close()` 删除目录。`close()` 同时清理所有本次创建的临时目录。
- **失败清理**：暂存目录在 `finally` 中递归删除；权限建立、发布、复核任一阶段失败都不在目标位置留下新明文，也不留下 `.gulupai-private-*` 残留。
- **特殊路径拒绝**：目标是符号链接、重解析点、非普通文件或目录时拒绝（错误消息含"链接""目录"），不跟随链接写入；错误消息不包含口令。

### 2.2 `DemoSeedService` 接入

- `seed(...)` 用 `try (PrivateCredentialFiles privateFiles = PrivateCredentialFiles.create())` 包住整个播种流程；两个临时 JSON（`PrivateJson`）在内部 `try/finally` 中 `close()`。
- `writePrivate` 只负责拼文件内容，明文交给 `writePrivateCredentials`；`readPasswords` 走 `readExistingPrivateCredentials`。
- 删除了 `restrictToOwner`、`deleteIfExists` 以及 `PosixFileAttributeView`、`Files` 等直接写文件的代码——凭据文件不再有绕过私有保护的路径。
- 重复播种时读取既有口令再发布，既有口令不变。

## 4. T3-2 定位

旧脚本用 PowerShell 管道等待 `pg_ctl start`：

```powershell
& $pgCtlExe ... 2>&1 | Tee-Object -FilePath $startLog | Out-Null
```

`pg_ctl` 启动的 `postgres` 继承了管道的写句柄并常驻，PowerShell 会一直等管道 EOF，因此 `pg_ctl` 早已返回、`pg_isready` 已能连上，脚本却卡在这一行，60 秒超时后以退出码 2 结束，永远进不了 Maven。

复现（标准 PostgreSQL 17.8，非沙箱终端）：同一行在 30 秒后仍未返回（打印 `PIPELINE STILL BLOCKED AFTER 30s`），而 `start.log` 已写"服务器进程已经启动"、`pg_isready` 返回 0；执行 `pg_ctl stop` 后管道立即解除。结论：不能以管道 EOF 判定 `pg_ctl` 结束。

## 5. T3-2 实现

### 5.1 `scripts/pg-test-process.ps1`：有界原生进程执行

- `Invoke-BoundedProcess`：用 .NET `Process`（`UseShellExecute=false`、`ArgumentList` 逐项传参、不用命令行字符串拼接）启动；stdout/stderr 各自重定向并异步复制到日志文件；以 **`WaitForExit(毫秒)` 的返回值**判定结束，超时则 `Kill($true)` 并在有界时间内等待退出。返回 `ExitCode/TimedOut/Duration/DurationMs/StdoutPath/StderrPath`，超时时 `ExitCode` 为 `$null`。
- `Start-ResidentProcess`：用于常驻 `postgres`，启动后立即返回进程句柄，同时持续排空两个管道，**从不等待退出**。
- `Close-ResidentProcess`：只在有限时间内等待，然后释放流与句柄。
- 由此所有外部命令都有明确上界，等待中的进程本身受外层期限约束，不会再有"进程还活着、脚本等 EOF"的情况。

### 5.2 `scripts/run-pg-tests.ps1`：阶段化生命周期

阶段顺序与日志（同时打印并写入运行目录 `log/stages.log`）：

```
PRECHECK → INITDB → START_SERVER → WAIT_READY → CREATE_DATABASE → RUN_MAVEN
        → STOP_SERVER → RESTORE_ENV → CLEANUP → EXIT
```

- 每个阶段打印 `[STAGE] 开始` 与 `[STAGE] 成功/退出码 N，耗时 X ms`；失败时 `EXIT` 阶段打印失败原因与脚本调用栈。
- 新增参数：`-StartMode Auto|PgCtl|Direct`（默认 Auto）、`-InitdbTimeoutSeconds`（300）、`-StopTimeoutSeconds`（60）；原有 `-PgBin`、`-Port`、`-JavaHome`、`-Maven`、`-MavenArgs`、`-StartupTimeoutSeconds`、`-KeepData` 保留。
- 各步骤超时：`java -version` 30s、`mvn -v` 120s、`pg_ctl --version` 30s、`initdb` 300s、`pg_ctl start` 启动期限+30s、单次 `pg_isready` 取 min(5s, 剩余期限)、`createdb` 60s、`pg_ctl stop` 60s。就绪循环每轮都检查剩余期限，直启模式每轮还检查常驻进程是否已退出。
- **启动**：Auto 先走 `pg_ctl start`；只有失败且日志含"继承套接字/inherited socket"才回退直启 `postgres.exe`；`PgCtl` 模式失败即失败；`Direct` 直接常驻启动。直启启动后立即检查进程是否已退出，退出则带日志尾部报错。
- **停止**：`Stop-OwnPgInstance` 只按本次数据目录停实例，证据链为：`postmaster.pid` 记录的目录等于本次数据目录 → `Get-Process` 句柄可打开 → `Process.Path` 等于本次 `postgres.exe` → `Process.StartTime` 与 `postmaster.pid` 第三行时间相差 ≤5 秒 → `Win32_Process.CommandLine` 引用本次数据目录（CIM 不可用时提示并降级为前三项证据）。任一证据不成立就不停止、保留目录并报清理失败。证据齐全后先 `pg_ctl stop`（有界），仍在则 `Kill($true)` 并有界等待。
- 路径比较用 `ConvertTo-NormalizedPath`（绝对化、`/`→`\`、去尾部反斜杠），修复了"命令行写 `D:/…`、脚本写 `D:\…` 导致误判归属"的问题。
- `Read-LogFile` 统一把空文件返回为空字符串，修复空日志导致的空引用异常。
- 环境快照/恢复覆盖 `TEST_DB_URL/TEST_DB_USERNAME/TEST_DB_PASSWORD`、`MAVEN_OPTS`、`JAVA_HOME`、`MAVEN_USER_HOME`；`finally` 分三层（停止实例 / 恢复环境 / 清理目录），任一层异常只置"清理失败"，不吞掉 Maven 退出码。
- 退出码：未进入 Maven（环境或起库失败）→ **2**；Maven 失败 → **Maven 原退出码**；Maven 成功且清理成功 → **0**；Maven 成功但实例停止或目录清理未完成 → **3**。
- 构建前清除 `target/classes`、`target/test-classes` 的只读位（沙箱环境 Maven 会把资源写成只读，属可丢弃产物）。
