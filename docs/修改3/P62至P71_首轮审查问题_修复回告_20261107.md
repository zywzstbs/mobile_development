## 2. 默认策略与影响

修复指南要求的两项默认实施策略已按选定方案落地，需要产品与前端确认。

1. **A14 残缺目录返回 503。** 只要出现无法准确投影的 ACTIVE 授权（缺角色/能力/范围、身份或资格异常、凭据缺失、待审/驳回），整份目录返回 503 `SERVICE_UNAVAILABLE`，message 固定为“管理员目录存在待核对的授权，请联系平台维护人员”。响应体不含 `items`，不输出任何看似完整的成员列表。这是“宁可不可就绪，也不显示虚假 ACTIVE”的保守选择，代价是一条异常记录会阻断整个目录读取。
2. **诊断只进内部日志。** 记录 `grantId`、`userId` 与缺失事实代码（`SUPER_ADMIN_ROLE_MISSING`、`CAPABILITY_MISSING`、`SCOPE_MISSING`、`IDENTITY_NOT_VERIFIED`、`ELIGIBILITY_NOT_VERIFIED_ACTIVE`、`CREDENTIAL_MISSING`、`ACCOUNT_NOT_USABLE`），不记录密码哈希、凭据、用户 DTO 或核验材料；接口不返回异常目标。
3. **合法学校范围管理员仍是 ACTIVE。** 目录有效性按选中授权行自身事实判断，没有套用 `isPlatformRecoveryAdmin`；全平台恢复能力仍由原谓词判断，学校范围操作者直调全局目录继续 403。
4. **坏 outbox 载荷保留待核对。** 载荷无法精确投递时不写通知、不写 `processed_at`，只记 `outboxId/eventType/reason`。队列可用性边界已确认：连续坏事件若占满最早 50 条，会阻塞后续批次。本轮不新增隔离或自动重试状态，也不把坏事件标成投递成功；真实业务库若有此类样本，需按修复指南 §5.5 由有权限的运维核对后单独处理。
5. **已读动作与 drain 是两个事务。** `POST /me/notifications/read-actions` 先提交已读，再调用 drain；drain 失败时外层 5xx **不能**作为“已读未发生”的证明。本轮用真实触发器失败验证了这一点，客户端与服务端说明均按此事实记录。
